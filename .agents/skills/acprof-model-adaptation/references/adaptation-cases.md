# 模型适配案例

这里只维护诊断顺序与可复用的验收问题。manifest、接口与依赖的当前定义见[运行兼容](../../../../docs/models/runtime.md)，不固化历史版本号或模型的永久支持结论。

| 场景 | 先核对 | 适配与验证重点 |
| --- | --- | --- |
| Ultravox / 自定义 pipeline 任务冲突 | Hub 元数据、Auto loader 提示、显式 task、custom pipeline 及完整 SHA | 通用 feature-extraction 提示不能独自覆盖具体任务语义；保存冲突与来源，实测输入映射和输出 |
| 主模型公开，依赖 gated | 固定 revision 下声明或静态发现的依赖与逐仓访问结果 | 区分主模型可见、依赖访问及真实加载；权限失败不靠替换模型隐藏 |
| MOSS 等需要独立 runtime | 当前 Python/Transformers/系统依赖契约及可共享环境 | 锁解析、真实容器 `pip check`、离线加载和输出验证；避免为一个模型放宽全部环境 |
| BLIP 图像描述 / 新输出模态 | 正式输入、预处理、生成参数和最终输出类型 | 共享四阶段协议、序列化、输入尺度与 profiler 使用相同 workload |
| 无 Torch 的 ONNX 等 backend | backend 声明、按需导入与指标适用性 | 真实加载/推理，框架无关指标可用；不能因为 Torch 不适用就把全部采集判为失败 |
| 本地自定义代码缺少传递导入 | 固定 snapshot 的相对导入、依赖文件和加载条件 | 静态解析不导入模型；隔离运行时验证离线依赖闭包，不盲目增加全量下载 |

## 失败路径与证据

根据实际改动选择路由冲突、未知架构、缺失依赖、错误 dtype、输入模态丢失、截断、序列化或输出无效等用例。期望行为来自上游接口和项目契约，不照抄被测实现作为答案。

声明或随机小模型 fixture 通过不能代替真实 checkpoint；一次 CPU/GPU 推理也不代表全部 profiler 兼容。真实运行缺少资源或访问条件时明确未验证，保留可复现命令与所缺条件，不取消这些边界来宣称支持。

更新支持范围只写已证明的接口、输入与设备，按 [manifest 与能力证据](../../../../docs/models/extensions.md#扩展声明与按需加载)关联来源。数值字段受影响时再进入 schema 变更流程。
