# 终端界面使用指南

TUI 提供实验配置、运行监控、实验结果、统计报告、镜像管理和设置。
在“实验结果”页选择并读取实验后，可展开“性能深度分析”，按需补采缺失的 Profiler 指标；补采不是独立页面。
在“统计报告”页选择实验后可生成、打开和导出离线 HTML；导出在完整写入后发布且拒绝覆盖已有目标，完整步骤见[交互式 HTML 报告](tui-pages.md#交互式-html-报告)。
先完成[安装与主机准备](../getting_started/installation.md#快速开始)，再启动界面。
设置文件格式与颜色参数见 [CLI 与设置](configuration.md#tui-本地设置)。

顶栏显示当前 Linux、VM、容器或 WSL2 环境及能力等级；完整 Native 硬件条件仍需预检确认。
采集确认页列出会采、语义降级与缺失指标；WSL2 的 full 或未开放 profiler 请求会在启动前拒绝。
平台策略见 [WSL2](../platforms/wsl2.md)，这些界面显示不进入正式测量窗口。

无 Docker 环境选择 Smoke/basic，在高级参数选择 Process 并点击“使用 Process 继承限制”。
预检显示 Runtime 选择、可用采集器和权限缺项；计划、结果及统计保留继承限制的标识。
完整操作及已验证/未验证边界见 [Linux Runtime](../platforms/linux-runtimes.md)。

输入模型 ID 后，唯一且证据完整的推理接口自动选择。存在多个独立推理配置时，下载权重前显示“选择采集任务”。顶部显示共同配置和用途／采集组数量，
每项显示用途名称、计算差异及代表输入；每组只测代表输入，其余用途保留声明。
点击复选框或用途文字选择，方向键切换、空格勾选，底栏可全选、取消或开始所选任务。
长参数可滚动查看，底栏保持可见。完整识别依据、组件和指纹保存在实验元数据，不在普通界面堆放原始 JSON。
信息不足或矛盾时请求补充配置；底层架构的潜在任务不会混入可执行路径列表。
选择后独立验证加载、输入处理、推理和输出，验证通过才开始正式采集；失败不会自动换任务。
中英文界面使用相同数据和稳定任务 ID，详见[任务发现与选择](../models/routing.md#任务发现与选择)。
