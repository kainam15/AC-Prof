# 终端界面使用指南

TUI 提供实验配置、运行监控、实验结果、补采实验、镜像管理和设置；统计报告位于实验结果中。
“设置”位于左侧导航栏最底部，分隔线随其靠下排列；展开与折叠时位置一致。

再次点击左侧活动栏中已选中的项目，可在完整侧边栏与仅显示图标之间切换；折叠后主内容区自动加宽，悬停图标可查看页面名称。
点击其他项目只切换页面并保留侧边栏当前状态；折叠时需再次点击已选中的项目才会展开。方向键配合 `Enter` 支持相同操作。折叠状态在本次会话的语言切换、窗口缩放、`F2` 与内部页面跳转后保留，表单草稿不会丢失。

Docker 准备失败可重新检查、按能力修复缓存或重新准备环境；下载、构建及准备／测量耗时见[准备进度与恢复](tui-pages.md#docker-准备进度与恢复)。
`auto` 遇到预构建标签缺失、架构不兼容或连接失败时，监控页显示回退警告、原因和本地构建进度。
成功回退会继续准备；最终失败对话框显示分类摘要，Docker 原始诊断保留在可展开详情和准备日志中。
下载预算、认证与内容校验错误的处理见[GHCR 恢复流程](../models/images.md#ghcr-不可用时恢复)。
Docker 下载源在“应用设置 → 管理连接与权限”配置；下载确认页显示来源、代理证据、缓存状态和条件性回退。
下载估算保留已知体积和未知项；运行时分别展示当前活动、Docker 累计 payload、资源体积与缓存复用，
仅在范围一致且分母可靠时显示当前对象的百分比，详见[下载统计口径](../models/images.md#下载总量与传输统计)。
构建前端失败单独显示目标 Registry 与原因，提供“重新预检并重试”；修改来源后需返回配置并重新启动。
配置含义与网络边界见[镜像下载来源](../models/images.md#下载来源分流限额-vpn-场景)。
镜像删除确认页列出目标的全部标签与仓库 digest；“无标签”镜像仍可能有 digest 引用，确认后会一并处理。
删除规则及失败原因见[镜像管理与清理](../models/images.md#镜像管理与清理)。
数据质量与 Profiling 状态共享同一快照；读取期间源数据变化时提示刷新。
连续切换实验或 JSON 报告时，新选择可以先于尚未结束的旧读取显示；旧结果不会覆盖当前选择。所有后台读取完全结束前仍禁止开始采集，避免与测量争用资源。
“实验结果”以实验目录为共享选择入口，选中、编辑路径或恢复历史实验后自动加载概览，并异步检查数据及 Profiling 状态。
概览首屏先显示运行状态、已完成 case 数、有效正式窗口和可用的下一步操作；“续跑”仍进入原有恢复检查及预检流程。case 总数缺失时不显示假定的百分比。
模型、运行、资源和产物按“身份 / 运行 / 资源 / 产物”分组。Run ID、精确到秒的本地时间、revision 和路径在各组的“更多信息”中展开；保存的原始时间和异常不会改写。
长值按终端格宽从中间截断，悬停可查看全文；用 Tab 聚焦可交互的值后，Enter 打开全文详情，C 请求复制完整值。剪贴板是否接收仍取决于客户端终端。
“文件已生成”只说明产物存在；有效窗口由既有数据检查确定，检查中、无法核验与确认零窗口分别显示。问题按“问题 / 影响 / 下一步”展示，原因码、原始异常和路径保留在折叠的技术详情。
有效窗口与质量状态在后台补齐，详细性能统计由 HTML 展示。失效的历史路径保留在设置中，不自动选中；可用“刷新实验状态”重试，并在输入框中横向查看完整目录路径。
“补采实验”与结果页共享选择和检查状态，选择实验不会启动 Profiler。检查后点击“补充性能分析”选择工具、查看计划或确认执行；启动前再次验证数据及互斥状态，结束、失败或取消后刷新状态。
补采首屏先说明尚未选择、检查中、检查取消、条件未通过、可补采或无需补采；已过期的检查要求重新核验。
无法补采时按“问题 / 影响 / 下一步”展示，选择实验和重新检查按钮紧贴提示。独立 CSV 缺少补采所需的来源信息时会说明这一限制，不影响已有统计数据的查看；原始路径和异常放在折叠的“技术详情”中，并可复制全文。
可补采时按工具分组显示状态；顶部计数为工具项数，各工具的完成数沿用既有结果记录口径，不表示 case 数或正式窗口数。实验来源默认折叠，采集期间不新增状态投影或刷新。
工具选择弹窗中的实验路径、工具状态和说明可滚动查看；底部的取消、计划预览和执行按钮保持可见，缩放窗口不清空勾选。
“实验结果”显示“概览”“分析报告”。选择实验后点击底栏“生成 HTML 分析”，在“分析报告”查看状态、路径并打开报告；SSH 无桌面环境可下载到本机打开。底栏“生成 PNG 图表”可为同一实验生成静态图表。五个统计参数输入框已迁入 HTML，交互图表、比较与当前结果导出也在 HTML 完成。旧统计数据、比较和导入 / 导出控件保持隐藏，后端及 CLI 能力保留。`/stats` 与 `/report [json]` 处理逻辑保留，执行后也不会重新显示隐藏区域，详见[统一分析流程](tui-pages.md#统计报告)。
先完成[安装与主机准备](../getting_started/installation.md#快速开始)，再启动界面。
设置文件格式、连接配置的保存与冲突处理、颜色参数见 [CLI 与设置](configuration.md#tui-本地设置)。
启动时还会[检查 PyPI 版本](tui-pages.md#启动和页面)，发现新版后提示升级命令；检查结果可在“应用设置 → 版本更新”查看。
Windows 原生可打开 TUI 编辑配置、检查版本和查看环境诊断；预检仍会阻止原生采集，
运行实验请使用受支持的 [Linux 或 WSL2 环境](../platforms/linux-runtimes.md)。

顶栏按异常、警告、通过分别显示机器环境检查数量，各组可独立固定；详情面板每次显示一组，并保留各组的固定状态。选中检查项后，下方持续显示其详情；悬停其他项目时临时预览，移开后恢复选中项详情。平台与检查证据见面板，完整 Native 硬件条件仍需预检确认。
采集确认页列出会采、语义降级与缺失指标；WSL2 的 full 或未开放 profiler 请求会在启动前拒绝。
平台策略见 [WSL2](../platforms/wsl2.md)，这些界面显示不进入正式测量窗口。

无 Docker 环境选择 Smoke/basic，在高级参数选择 Process 并点击“使用 Process 继承限制”。
预检显示 Runtime 选择、可用采集器和权限缺项；计划、结果及统计保留继承限制的标识。
完整操作及已验证/未验证边界见 [Linux Runtime](../platforms/linux-runtimes.md)。

输入模型 ID 后，唯一且证据完整的推理接口自动选择。存在多个独立推理配置时，下载权重前显示“选择采集任务”。顶部显示共同配置和用途／采集组数量，
每项显示用途名称、计算差异及代表输入；每组只测代表输入，其余用途保留声明。
点击复选框或用途文字选择，方向键切换、空格勾选，底栏可全选、取消或开始所选任务。
长参数可滚动查看，底栏保持可见。完整识别依据、组件和指纹保存在实验元数据，不在普通界面堆放原始 JSON。
信息不足或矛盾时请求补充配置；底层架构的潜在任务不会混入可执行路径列表。
选择后独立验证加载、输入处理、推理和输出，验证通过才开始正式采集；失败不会自动换任务。
中英文界面使用相同数据和稳定任务 ID，详见[任务发现与选择](../models/routing.md#任务发现与选择)。

## 打开 HTML 报告

“分析报告”中的“打开”请求系统打开**已有的本地 HTML 文件**，不会在 TUI 内嵌网页、
重新生成报告或启动 HTTP 服务。完整路径自动换行；“复制路径”与“打开”并列，
沿用终端剪贴板支持，不会把服务器文件自动下载到本机。

| 运行会话 | 打开方式 |
| --- | --- |
| Windows 原生、macOS、Linux 桌面 | 保留 Python `webbrowser` 默认浏览器调用；Linux 需要桌面显示变量 |
| 本地 WSL1 / WSL2 | 不要求 Linux 的 `DISPLAY`；先使用可用的 `wslview`，缺失或明确失败时尝试 `wslpath` + Windows `powershell.exe` |
| SSH，包括 SSH 到 WSL、X11 转发 | 不启动远端浏览器；复制路径后用 VS Code / SFTP 获取文件，在客户端打开 |
| 本地纯命令行 Linux | 不回退到终端浏览器；复制路径，在有桌面的会话中打开 |

WSL 的 Windows 互操作必须可用，后备命令须在 `PATH` 中；AC-Prof 不安装 `wslu`、
不修改 `BROWSER`、Shell 配置或系统默认应用。通过 `wslpath` 转换 Linux/挂载盘路径，
不把 `file:///home/...` 直接交给 Windows。包含 Shell 特殊字符的路径跳过可能插值的
`wslview` 路径，直接使用以数据传递文件名的 PowerShell 后备方式。
桥接不可用时保留具体错误；可从 Windows 文件资源管理器的 **Linux → 对应发行版**
进入报告目录手动打开，不必下载或架设服务。浏览器桥接不改变 WSL 的采集支持等级。

状态依次为“正在请求浏览器打开”和“已提交打开请求（启动方式）”；后者只说明启动器
接受了请求，**不能证明浏览器已显示页面**。明确失败会保留启动器名称、退出码和诊断；
每次 WSL 子调用设 5 秒超时，超时时请求状态标为未知且不自动重试，避免重复打开。
打开、失败及复制路径均不修改 HTML、统计结果和原始 CSV。

实现参考 [open 的 WSL/SSH 分流与路径转换](https://github.com/sindresorhus/open/blob/main/index.js)、
[Click 的 Windows 空格路径问题](https://github.com/pallets/click/issues/2994) 和
[wslview 的桥接实现](https://github.com/wslutilities/wslu/blob/master/src/wslview.sh)。
借鉴平台分流、进程参数与失败边界，不复制实现，也不新增运行依赖。
