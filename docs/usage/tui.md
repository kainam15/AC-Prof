# 终端界面使用指南

TUI 提供实验配置、运行监控、实验结果、补采实验、镜像管理和设置；统计报告位于实验结果中。
“设置”位于左侧导航栏最底部，分隔线随其靠下排列；展开与折叠时位置一致。

结果概览、补采实验、采集计划、环境详情、任务选择和监控页头采用一致的信息层级：先看状态和结论，再选择可用操作，按需展开事实与技术详情。
状态同时使用文字、符号和颜色；`✓` 表示已有成功证据，`!` 表示受限或需处理，`×` 表示失败或不可用，`-` 表示中性或尚待确认，`…` 表示正在进行。具体含义以对应页面的文字说明为准。

“实验配置”将计划集中在表单上方：先显示状态，再用一个“采集计划”网格列出运行方式、资源 case 数、输入规模、窗口总量和每条件正式窗口数。
少于三个正式窗口时标为“! 受限 · 仅验证流程”；这不禁止启动，也不表示已取得有效窗口。正常计划只说明计算完成，环境是否允许采集仍由预检决定。
展开“更多信息”可查看耗时假设、下载预算、请求超时、分析器、资源参数和完整路径；详情区域可滚动，底部“高级参数 / 探测最大输入 / 开始采集”保持可操作。
无效草稿改为显示问题、影响和下一步，并清空上一份计划的窗口数。输入规划消息在准备阶段更新计划；正式测量窗口内冻结计划展示。

“运行监控”先显示阶段结论和已有的运行时钟；Case 与资源分别使用键值网格，已知总数时显示静态进度条。
“已处理”沿用既有 case 计数，包含失败或跳过的 case，不代表有效正式窗口；总数未知或计数不一致时不绘制进度条。
验证信息按当前阶段出现，原因、警告与错误计数放进默认折叠的“运行详情”；原始异常可查看与复制全文，完整输出继续保留在日志中。
正式测量期间沿用原有日志暂停和刷新门控，进度条没有动画或额外计时刷新；底部“终止任务”保持可达。详情见[运行监控与日志](tui-experiments.md#日志查看与复制)。

再次点击左侧活动栏中已选中的项目，可在完整侧边栏与仅显示图标之间切换；折叠后主内容区自动加宽，悬停图标可查看页面名称。
点击其他项目只切换页面并保留侧边栏当前状态；折叠时需再次点击已选中的项目才会展开。方向键配合 `Enter` 支持相同操作。折叠状态在本次会话的语言切换、窗口缩放、`F2` 与内部页面跳转后保留，表单草稿不会丢失。

Docker 准备失败可重新检查、按能力修复缓存或重新准备环境；下载、构建及准备／测量耗时见[准备进度与恢复](tui-pages.md#docker-准备进度与恢复)。
`auto` 遇到预构建标签缺失、架构不兼容或连接失败时，监控页显示回退警告、原因和本地构建进度。
成功回退会继续准备；最终失败对话框显示分类摘要，Docker 原始诊断保留在可展开详情和准备日志中。
下载预算、认证与内容校验错误的处理见[GHCR 恢复流程](../models/images.md#ghcr-不可用时恢复)。
Docker 下载源在“应用设置 → 管理连接与权限”配置；下载确认页显示来源、代理证据、缓存状态和条件性回退。
下载估算保留已知体积和未知项；运行时分别展示当前活动、Docker 累计 payload、资源体积与缓存复用，
仅在范围一致且分母可靠时显示当前对象的百分比，详见[下载统计口径](../models/images.md#下载总量与传输统计)。
构建前端失败单独显示目标 Registry 与原因，提供“重新预检并重试”；修改来源后需返回配置并重新启动。
配置含义与网络边界见[镜像下载来源](../models/images.md#下载来源分流限额-vpn-场景)。
镜像删除确认页列出目标的全部标签与仓库 digest；“无标签”镜像仍可能有 digest 引用，确认后会一并处理。
删除规则及失败原因见[镜像管理与清理](../models/images.md#镜像管理与清理)。
存储空间弹窗采用分项查询与固定顶部反馈；失败、未知、不适用及带时间的历史读取分别展示，
刷新受阻时说明原因，详见[镜像管理](tui-pages.md#镜像管理)。
数据质量与 Profiling 状态共享同一快照；读取期间源数据变化时提示刷新。
连续切换实验或 JSON 报告时，新选择可以先于尚未结束的旧读取显示；旧结果不会覆盖当前选择。所有后台读取完全结束前仍禁止开始采集，避免与测量争用资源。
“实验结果”以实验目录为共享选择入口，选中、编辑路径或恢复历史实验后自动加载概览，并异步检查数据及 Profiling 状态。
概览首屏先显示运行状态、已完成 case 数、有效正式窗口和可用的下一步操作；“续跑”仍进入原有恢复检查及预检流程。case 总数缺失时不显示假定的百分比。
模型、运行、资源和产物按“身份 / 运行 / 资源 / 产物”分组。Run ID、精确到秒的本地时间、revision 和路径在各组的“更多信息”中展开；保存的原始时间和异常不会改写。
长值按终端格宽从中间截断，悬停可查看全文；用 Tab 聚焦可交互的值后，Enter 打开全文详情，C 请求复制完整值。剪贴板是否接收仍取决于客户端终端。
“文件已生成”只说明产物存在；有效窗口由既有数据检查确定，检查中、无法核验与确认零窗口分别显示。问题按“问题 / 影响 / 下一步”展示，原因码、原始异常和路径保留在折叠的技术详情。
有效窗口与质量状态在后台补齐，详细性能统计由 HTML 展示。失效的历史路径保留在设置中，不自动选中；可用“刷新实验状态”重试，并在输入框中横向查看完整目录路径。
“补采实验”与结果页共享选择和检查状态，选择实验不会启动 Profiler。检查后点击“补充性能分析”选择工具、查看计划或确认执行；启动前再次验证数据及互斥状态，结束、失败或取消后刷新状态。
补采首屏先说明尚未选择、检查中、检查取消、条件未通过、可补采或无需补采；已过期的检查要求重新核验。
无法补采时按“问题 / 影响 / 下一步”展示，选择实验和重新检查按钮紧贴提示。独立 CSV 缺少补采所需的来源信息时会说明这一限制，不影响已有统计数据的查看；原始路径和异常放在折叠的“技术详情”中，并可复制全文。
可补采时按工具分组显示状态；顶部计数为工具项数，各工具的完成数沿用既有结果记录口径，不表示 case 数或正式窗口数。实验来源默认折叠，采集期间不新增状态投影或刷新。
工具选择弹窗中的实验路径、工具状态和说明可滚动查看；底部的取消、计划预览和执行按钮保持可见，缩放窗口不清空勾选。
“实验结果”显示“概览”“分析报告”。选择实验后点击底栏“生成 HTML 分析”，在“分析报告”查看状态、路径并打开报告；SSH 无桌面环境可下载到本机打开。底栏“生成 PNG 图表”可为同一实验生成静态图表。五个统计参数输入框已迁入 HTML，交互图表、比较与当前结果导出也在 HTML 完成。旧统计数据、比较和导入 / 导出控件保持隐藏，后端及 CLI 能力保留。`/stats` 与 `/report [json]` 处理逻辑保留，执行后也不会重新显示隐藏区域，详见[统一分析流程](tui-pages.md#统计报告)。
先完成[安装与主机准备](../getting_started/installation.md#快速开始)，再启动界面。
设置文件格式、连接配置的保存与冲突处理、颜色参数见 [CLI 与设置](configuration.md#tui-本地设置)。
启动时还会[检查 PyPI 版本](tui-pages.md#启动和页面)；“应用设置 → 版本管理”支持渠道选择，
以及标准 `uv tool` 安装的一键更新、降级确认和重启，见[版本管理与恢复](version-management.md)。
Windows 原生可打开 TUI 编辑配置、检查版本和查看环境诊断；预检仍会阻止原生采集，
运行实验请使用受支持的 [Linux 或 WSL2 环境](../platforms/linux-runtimes.md)。

顶栏状态中心统一汇总配置、Runtime、资源权限和当前实验能力，区分阻断、警告、通过、待检查及未请求。
同一根因只统计一次；配置错误与采集门禁使用同一份 `GlobalStatus`。各组可独立固定，默认解释首个优先项而不改变键盘焦点；选中其他项可持续查看，悬停临时预览，移开后恢复选择。
异常按「问题 / 影响 / 下一步」展示；技术详情默认折叠，可滚动、复制。点击状态项或按 Enter 只查看说明，主动使用「定位问题」才打开配置字段或专用诊断。
字段定位后可用顶栏「返回」或 `Alt+Left` 回到原页面、焦点和滚动位置；关闭诊断弹窗也恢复原上下文。没有明确修复目标的错误只提供原因与重检，不跳到无关权限页面。
「本次检查」默认折叠，包含平台、本地时区的秒级检查时间、测量锁证据和检查范围。正式测量时只查看缓存，禁用重检。完整操作见[环境检查](tui-interaction.md#环境检查)。
采集确认页列出会采、语义降级与缺失指标；WSL2 的 full 或未开放 profiler 请求会在启动前拒绝。
平台策略见 [WSL2](../platforms/wsl2.md)，这些界面显示不进入正式测量窗口。

在首页“实验配置 → 基本配置”中，“模型来源”之后依次提供“运行方式”“画像模式”和“输出目录”。
“画像模式”可选择完整（RAPL / perf / 抓包）或基础（延迟 / CPU / 内存），无需进入高级参数。
CPU 列表、内存 GB、GPU 模式和输入规模集中在“资源矩阵”中，默认折叠；点击标题或聚焦后按 Enter 展开。
其下方的“测量参数”集中提供 Warmup、Repeat、采样频率、Idle 基线、冷却时间、连接/读取超时、
Batch size、窗口请求数和自动窗口，同样默认折叠；这些字段已从“高级参数”移至基本配置。
两个折叠区都会保留当前参数；配置校验需要定位其中的错误字段时，会自动返回基本配置、展开并聚焦该字段。
“测量参数”下方提供默认折叠的“深度性能分析”，包含 PyTorch Profiler、NVIDIA NCU、Valgrind Massif 和 NVIDIA Nsys。
点击标题或聚焦后按 Enter 展开；收起后保留勾选状态，原有按需选择说明和配置保存方式保持不变。
Auto / Docker / Process 的默认值和保存方式保持不变：“记住实验配置”会保存当前选择，
下次启动时恢复；进入高级参数再返回也会保留配置。
Auto 预检成功后，最终 Runtime 显示在采集计划，不再重复显示蓝色说明；Process 仍保留必要的配额限制提示。
切换运行方式会刷新计划与完整命令，使不匹配的旧预检结果失效；CPU、内存、GPU 等输入不会自动改变。

Process 数值配额遇到权限问题时，保持当前页面、焦点和滚动位置，CPU/内存字段只保留简短错误标识。
从状态中心主动「定位问题」进入 Process 专用诊断，可重新检查、查看详细原因或选择使用继承限制。
详情包含 cgroup 委派、控制器及配额证据，管理员命令只展示，AC-Prof 不执行。高级参数仍提供固定 CPU 集合，不再常驻大块权限说明。
“使用继承限制”须确认后才把 CPU、内存设为 auto，并明确不保证数值配额或资源独占；取消保持原值，权限失败不会自动选择此项。
预检通过后，实际启动仍验证实验进程的 cgroup 归属和配额。具体环境指引见[Process 资源权限](troubleshooting.md#process-资源权限)。

perf / tcpdump 权限问题的「定位问题」直接打开“连接与权限 → 采集权限”并聚焦对应选项。
勾选只表示待配置目标；变更仍经过命令预览、确认和原有 sudo 授权。执行后重新检查实际权限并同步状态中心，失败保留原因，不以命令成功代替能力通过。
Docker 与 RAPL 问题各有对应诊断和权限说明。

配置改动后立即更新字段校验；相关设置停止修改约 500ms 后自动预检，旧结果转为待检查，不放行新配置。
Warmup、Repeat 和窗口请求数只刷新表单与计划；Process CPU／内存配额变化会重新验证资源。
采集计划保留配置摘要、统计质量和测量参数；配置问题集中在状态中心及对应字段，不再重复显示整段“配置待完善”。
只有配置有效、必要预检已有通过证据且没有冲突任务时才启用“开始采集”。详见[自动配置检查](tui-interaction.md#自动配置检查)。
未请求的可选工具及无关 Docker 能力不阻断 Basic 采集；独立补采工具的失败只影响对应补采，缺失指标继续显示未采集/不可用。

完整操作及已验证/未验证边界见 [Linux Runtime](../platforms/linux-runtimes.md)。

输入模型 ID 后，唯一且证据完整的推理接口自动选择。存在多个独立推理配置时，下载权重前显示“选择采集任务”。
顶部先说明用途／采集组数量及当前选择；“已选”只表示选择状态，不表示模型已通过运行验证。
共同配置使用键值网格，各任务组突出与共同配置不同的参数；次要参数、代表输入和完整任务 ID 按需展开，模型与 revision 收在默认折叠的“当前模型信息”。
点击复选框或用途标题选择，复选框聚焦时用方向键切换、空格勾选；详情与复制入口可通过 Tab 到达，Enter 展开详情，查看或复制参数不会改变勾选状态。
长内容可滚动查看，底栏的全选、取消和开始所选任务保持可见。每组只测代表输入，其余用途保留声明；完整识别依据、组件和指纹继续保存在实验元数据。
信息不足或矛盾时请求补充配置；底层架构的潜在任务不会混入可执行路径列表。
任务与推理配置确认并冻结后，独立验证加载、输入处理、推理和输出，验证通过才开始正式采集；失败不会自动换任务。
中英文界面使用相同数据和稳定任务 ID，详见[任务发现与选择](../models/routing.md#任务发现与选择)。

启动失败时，准备界面优先显示失败阶段、错误类型、简短原因和修复建议；架构不支持、依赖缺失、
模型文件不完整、加载失败、资源不足与推理异常分别提示。完整诊断默认折叠，避免框架的支持架构
长列表占据主要内容。Docker 服务启动失败会先保存完整 stdout/stderr，再清理所属容器；日志位于
`${XDG_STATE_HOME:-~/.local/state}/acprof/container-logs/<container-id>.log`，界面显示具体路径。
日志提取失败或不完整时明确报告原因，不宣称已经完整保存。静态 Backend 声明仍与实际运行验证分开。

## 推理参数与最终确认

任务范围确定后，准备阶段显示“模型推理配置”。页面复用模型及后端的统一声明，按照
推理后端、加载配置、推理配置和工作负载分区；CPU 与 GPU 的加载值分别展示。
模型固定属性只读；当前声明没有登记可验证消费者的参数不能作为可执行选项提交。

每个可调字段都有请求模式和类型化控件。枚举及布尔使用下拉框，数值和字符串使用输入框，
列表填写 JSON 数组；允许空值的字段另有“指定空值（null）”。“指定值”会保留明确选择，
即使数值等于默认值；“不设置”与“Auto（自动选择）”互不等同。
关闭随机采样等操作会按统一依赖声明禁用无效的值输入，并显示原因。已有显式冲突不会被
悄悄丢弃：可以恢复依赖，或主动将该字段改为“不设置”，再提交校验。

预设由已登记能力提供。选中预设后，还要点击“应用此预设”才会发送变更；
选择 Auto 预设会明确授权其字段使用自动规则。作者任务预设只在有固定 revision、原始摘要且无冲突的
`task_specific_params` 时显示，仅修改有对应作者值的字段。AC-Prof Benchmark v1 固定已登记的任务参数，
保留当前加载与 workload 选择；它是项目基线，不代表外部 Benchmark 认证。
切换后端、Runtime Profile 或改变参数声明范围后，系统刷新表单，再显示新的可用选项；
旧后端的证据不能代替新后端验证。

点击“查看最终配置”后，独立的“确认最终推理配置”页展示模型与固定 revision、后端、
Runtime Profile、按设备和任务划分的最终参数、来源、Auto 决策及内容摘要。
完整配置可滚动查看，底部操作保持可见。此处的静态校验不代表运行时已验证；
页面明确保留运行时验证尚未执行的状态。

点击“修改推理配置”返回编辑；编辑或切换后端后重新生成摘要。只有点击“确认并冻结”并
返回对应 SHA-256，系统才接受这份具体配置并开始后续模型准备。随后加载或推理验证发现
实际值与冻结配置不一致时，采集会终止。取消配置或确认页会返回配置阶段，不会启动正式采集。

“高级参数 → 识别覆盖”也可填写“推理请求 JSON”；非交互 CLI 的两步操作见
[CLI 推理配置](cli-run.md#推理配置先审阅再冻结)。除 native NLP 外，Whisper 语言、Chronos 预测长度、
多模态生成参数及 SDXL 参数／Scheduler 已登记消费者与观察方法；新增路线仍只有离线开发验证证据。
详细协议与支持限制见
[推理配置契约](../models/inference-configuration.md)。

## 打开 HTML 报告

“分析报告”中的“打开”请求系统打开**已有的本地 HTML 文件**，不会在 TUI 内嵌网页、
重新生成报告或启动 HTTP 服务。完整路径自动换行；“复制路径”与“打开”并列，
沿用终端剪贴板支持，不会把服务器文件自动下载到本机。

| 运行会话 | 打开方式 |
| --- | --- |
| Windows 原生、macOS、Linux 桌面 | 保留 Python `webbrowser` 默认浏览器调用；Linux 需要桌面显示变量 |
| 本地 WSL1 / WSL2 | 不要求 Linux 的 `DISPLAY`；先使用可用的 `wslview`，缺失或明确失败时尝试 `wslpath` + Windows `powershell.exe` |
| SSH，包括 SSH 到 WSL、X11 转发 | 不启动远端浏览器；复制路径后用 VS Code / SFTP 获取文件，在客户端打开 |
| 本地纯命令行 Linux | 不回退到终端浏览器；复制路径，在有桌面的会话中打开 |

WSL 的 Windows 互操作必须可用，后备命令须在 `PATH` 中；AC-Prof 不安装 `wslu`、
不修改 `BROWSER`、Shell 配置或系统默认应用。通过 `wslpath` 转换 Linux/挂载盘路径，
不把 `file:///home/...` 直接交给 Windows。包含 Shell 特殊字符的路径跳过可能插值的
`wslview` 路径，直接使用以数据传递文件名的 PowerShell 后备方式。
桥接不可用时保留具体错误；可从 Windows 文件资源管理器的 **Linux → 对应发行版**
进入报告目录手动打开，不必下载或架设服务。浏览器桥接不改变 WSL 的采集支持等级。

状态依次为“正在请求浏览器打开”和“已提交打开请求（启动方式）”；后者只说明启动器
接受了请求，**不能证明浏览器已显示页面**。明确失败会保留启动器名称、退出码和诊断；
每次 WSL 子调用设 5 秒超时，超时时请求状态标为未知且不自动重试，避免重复打开。
打开、失败及复制路径均不修改 HTML、统计结果和原始 CSV。

实现参考 [open 的 WSL/SSH 分流与路径转换](https://github.com/sindresorhus/open/blob/main/index.js)、
[Click 的 Windows 空格路径问题](https://github.com/pallets/click/issues/2994) 和
[wslview 的桥接实现](https://github.com/wslutilities/wslu/blob/master/src/wslview.sh)。
借鉴平台分流、进程参数与失败边界，不复制实现，也不新增运行依赖。
