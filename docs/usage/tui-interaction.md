## 快捷键与退出

`F1` 打开快捷键说明；非输入控件上按 `?` 也可打开，在输入框中仍输入普通问号。
`F2` 或 `/settings` 打开应用设置，`F3` 切换基本配置与高级参数，`F4` 打开模型候选，
`F5` 开始采集，`F6` 执行环境检查，`F8` 放大或还原日志，`Ctrl+X` 安全终止当前任务。
说明弹窗按 `F1`、`?` 或 `Esc` 关闭；其他弹窗打开时不会再叠加快捷键说明。
弹窗操作按钮聚焦后可用 `←` / `→` 在可用按钮间移动，输入框内仍保留光标编辑。
点击界面右上角的“×”或按 `Ctrl+Q` 退出；任务运行中会提示先安全终止任务。
环境警告、异常或能力提示显示在“×”左侧，退出入口始终保留在最右端。
底部快捷命令框默认隐藏，可在设置页勾选“显示底部快捷命令框”启用。
启用后支持 `/run`、`/probe`、`/check`、`/status`、`/stop`、`/plot`、`/stats`、`/report`、`/images`、`/profile` 和 `/help`
等快捷命令。

搜索选择器支持拖动列宽和点击表头排序，排序保留当前所选记录；在搜索框按 `↓` 进入列表，
再按 `Enter` 执行该记录的首个可用动作。模型或实验详情分为状态、事实及必要的失败说明，完整值仍可查看和复制。
日志搜索用 `Enter` 跳到下一处、`Shift+Enter` 跳到上一处，状态栏显示当前匹配序号和总匹配数。
正式测量期间继续暂停日志搜索和展示更新，结束后恢复。

任务进入“正在创建子进程”后即可使用“终止任务”或 `Ctrl+X`。确认停止时若还在读取历史产物、
尚未创建子进程，本次启动会取消；读取工作退出前仍保持占用，结束后可直接重新开始。
若子进程已在创建，TUI 会在取得进程后按现有 SIGINT / SIGTERM 清理流程安全停止。

### VS Code 中的 Ctrl+Q

如果 `Ctrl+Q` 在普通终端有效、在 VS Code 集成终端无效，可能是按键被 VS Code 拦截。
Windows 客户端默认将它绑定到“快速打开视图”（`workbench.action.quickOpenView`）；
Remote-SSH 也由发起连接的客户端处理快捷键。在 VS Code 工作区设置 JSON 中加入
以下配置；已有 `terminal.integrated.commandsToSkipShell` 数组时，将该条目追加进去：

```json
{
  "terminal.integrated.commandsToSkipShell": [
    "-workbench.action.quickOpenView"
  ]
}
```

前缀 `-` 表示将该命令移出终端按键拦截名单，让终端应用接收按键。
参见 [VS Code 官方终端快捷键说明](https://code.visualstudio.com/docs/terminal/advanced#_keyboard-shortcuts-and-the-shell)。
保存后点击终端让其获得焦点，再按 `Ctrl+Q`。若仍无效，运行命令面板中的
`Developer: Toggle Keyboard Shortcuts Troubleshooting`，再按一次 `Ctrl+Q`，查看
快捷键日志中实际匹配的命令，以排查扩展或自定义绑定；排查后再次运行该命令关闭日志。
也可以点击右上角“×”，或在底部快捷命令框输入 `/quit` 退出。

## 环境检查

页头右侧汇总整机能力与当前实验的配置校验、Runtime 兼容性、资源权限，与“开始采集”
使用同一状态快照。`×` 是阻断错误，`!` 是不阻断的能力或数据质量警告，`✓` 只统计已通过检查。
`…` 单独统计待检查、检查中或已过期结果；`-` 仅用于没有整机检查证据的实验未请求项，均不计入正常。
整机结果不受采集开关筛选：未启用的能力仍按成功证据、缺失或待验证结果计入对应组，缺失作为警告。
当前配置的必要预检决定是否阻断；未请求占位项不能覆盖同一能力已有的整机结果。
同一根因按稳定检查 ID 去重，配置字段旁的错误提示仍保留。Process 模式不兼容与配额权限失败
是独立问题；同一配额诊断在局部提示和全局列表中只计一次。
平台、最近整机检查时间、测量锁证据及检查范围收在默认折叠的“本次检查”；自动配置检查不改写
整机扫描时间。通过仅表示对应配置校验、环境检查或预检通过，不代表真实模型、GPU 或完整 Profiler 验收。

鼠标悬停某组符号或数量时展开该组的检查结果，数量为零时明确提示没有对应检查项。
各组是独立入口，没有下划线；入口之间与右侧空白不触发。一次只显示一个类别的详情，
点击入口固定该类别，切换类别时各自记住固定状态，不会把上一类别的固定状态带给当前类别。
再次点击入口取消该类别的固定；点击外部或按 `Esc` 关闭并取消当前类别的固定，其他类别不受影响。
移入面板后保持打开；未固定时离开入口和面板约 180 ms 后收起，其他模态窗口也会隐藏未固定面板。
键盘可用 `Tab` / `Shift+Tab` 分别聚焦各组，`Enter` 或 `Space` 切换该组的固定状态。
固定的入口用独立底色和粗体标识，键盘焦点用粗体标识，保留状态颜色。
面板覆盖下方内容，不挤压表单，窄终端内可滚动。异常项的「重新检查」紧贴问题的恢复建议；
查看正常、待确认项或空分组时，详情区提供同一个重检入口。不可执行时显示禁用原因。

启动时默认检查全部机器能力，无需填写模型，也不受实验选项影响：

- Docker CLI、daemon、本机 socket、cgroup v2，以及 Process 的 uv 和进程监管；
- 当前进程 CPU / 内存读取、本机 cgroup CPU / 内存接口、RAPL、perf、抓包工具与权限、网络接口；
- 所有 NVML 可见 GPU 的设备、显存、利用率、功耗，逐个设备和指标报告读取结果；
- Nsight Compute、Nsight Systems、Intel Advisor 的自动发现与有时限的版本查询，
  以及 Torch Profiler、Massif 在本地 Runtime 内的最小 CPU 自检。

检查项使用与顶栏一致的 `× / ! / ✓ / … / -`，并显示功能名称和状态文字，不只依靠颜色。
通过只表示该项已有成功证据；不可用、检查失败、受限、待确认及未请求分别保留原有含义。
阻断与受限项优先排列，未知状态保持待确认；必需检查未确认时不能开始采集。
面板按实际来源分为「基础环境」「Docker / cgroup」「Process Runtime」「NVIDIA NVML」、
「Linux RAPL」「Linux perf」「网络抓包」和「Profiler」。配置校验归「配置检查」，
预检执行异常与尚未登记的新检查归「其他检查」，不会丢弃。
顶栏筛选选出含对应状态的来源；展开后保留该来源的全部检查，因此成功和局部失败可以同时看到。
来源标题汇总检查中、通过、警告、错误、待验证或未请求，异常数量按根因统计；
只有全部适用检查通过才显示通过，过期或未知检查不会计入通过。
正常来源默认折叠，异常来源默认展开；点击标题或用 Enter / Space 展开、折叠并查看来源诊断。
手动选择在状态刷新、筛选切换和语言切换后保留，未手动操作的来源随状态更新默认展开方式。
来源按单列排列，窄窗下也保留名称和状态，列表与详情可分别滚动。

同一来源内的已确认根因只计一个问题，例如缺少 tcpdump 导致权限无法验证、NVML 初始化失败、
Docker 不可用导致 Torch / Massif 自检无法执行。展开后各项原始检查 ID、结果与诊断仍保留。
不会仅凭相同工具名或相似报错合并；显存正常而功耗异常时，显存仍显示通过。
来源说明分别列出环境检查、本次请求及尚待 Runtime 确认的数量。
仅当前已请求且异常的能力提示存在缺失风险的主要字段；未请求项的安装或权限问题不影响启动门禁。
工具缺失提供 Linux / WSL 对应安装说明和官方文档，权限问题沿用已有权限页面；
指引本身不执行安装。修复后使用同一个“重新检查”入口验证。
预检通过不代表实际采集成功；实验结束后以“实验结果”的产物、质量及 Profiler 检查核对完整性，
不能把通过预检作为缺失字段已采集的证据。来源分组不改变 CSV、metadata 或跨 Runtime 指标语义。

打开类别后默认显示首个优先项的解释，不抢占当前键盘焦点。键盘聚焦查看解释；Docker 异常项点击或按 `Enter` / `Space` 直接打开安装与修复引导。其他检查项通过 Tab 到达“定位问题”再按 Enter，或直接点击该按钮，
才跳转对应配置字段、Process 专用诊断或权限弹窗。字段定位支持顶栏“返回”与 `Alt+Left`，关闭弹窗也恢复原页面、焦点与滚动位置；
没有明确目标的错误不提供无关跳转。查看成功项时点击只改变选择；
异常项按「问题 / 影响 / 下一步」说明限制及恢复方式，正常或待确认项以键值网格说明状态和验证范围。
悬停其他项目时临时预览，鼠标移到说明区、按钮或其他非项目区域后恢复选中项详情；焦点移到说明区不会丢失选择。
更新清单或切换语言时保留仍存在的选中项；原项不在当前类别中时改为该类别的首个优先项。
技术详情默认折叠，保留原始状态、能力码、来源、异常与路径；长输出经既有凭据脱敏后保留全文和换行，可滚动查看及复制。
`Tab` / `Shift+Tab` 可到达详情标题与复制入口，`Enter` 可展开或收起；`NO_COLOR` 下仍可从符号和文字理解状态。

| 状态 | 含义 |
| --- | --- |
| 检查中 / 待检查 | 当前必需检查正在执行、尚未执行或结果已过期，暂不能开始采集 |
| 就绪 | 配置与当前实验必需预检通过 |
| 受限 | 当前实验可开始，但存在可选能力或数据质量限制 |
| 阻断 | 当前配置或必需能力失败，修复后重新检查 |
| 未请求 | 当前实验不需要此项能力，且尚无对应整机检查证据；不影响采集门禁 |

模型 ID、Runtime 和 CPU／内存配置错误分别定位对应字段；Process cgroup 委派问题进入专用诊断，
失败本身不切换页面。“使用继承限制”必须确认，并说明不保证数值配额或资源独占。
perf / tcpdump 问题打开“连接与权限 → 采集权限”并聚焦具体选项；勾选配置目标与实际权限证据分别展示。
变更保留预览、确认和 sudo 流程；无论命令成功或部分失败，都重新检查实际能力并更新状态中心。
Docker、RAPL 进入各自诊断与修复指引。技术详情与页面导航只读取缓存，不执行宿主探测。

### Docker 安装与修复引导

从右上角全局状态点击 Docker 警告或阻断项，或点击说明中的“安装引导”。
引导默认显示原因、当前影响和推荐操作，按 Ubuntu、Debian、其他 Linux 或 WSL2 提供步骤；
底部“重新检查”始终可达。每组命令可复制，官方文档链接可打开或复制，底层诊断默认折叠。

| 检测结果 | 对应操作 |
| --- | --- |
| 未找到 Docker CLI | Ubuntu / Debian 提供官方 APT 源与 Engine 安装命令；其他发行版链接官方安装列表 |
| CLI 已安装但不在 PATH | 展示已发现的 CLI 路径，提供接入当前 PATH 的非覆盖软链接命令 |
| daemon 无法连接 | 按 systemd 或 Ubuntu / Debian 的 service 启动方式检查服务 |
| Socket 权限不足 | 先检查 Socket 所有者与用户组，再按需授权 docker 组 |
| Context 不存在或无法读取 | 保留失败原因，检查有效 Context、配置访问权限及环境变量 |
| Desktop、远程或 Rootless 端点 | 说明本机采集限制，核对 `default` 与 `desktop-linux`，由用户手动选择本机 Engine |
| 检查通过 | 自动更新全局状态；其他必要能力仍需分别通过 |

Docker 不可用但 Process 可用时只显示警告，不阻断 Process；明确选择 Docker 时故障阻断采集。
原生 Linux 推荐 Docker Engine。WSL2 仅支持 PARTIAL，Docker Desktop 的 WSL 集成不替代当前发行版内的本机 daemon；
Windows、macOS 和未确认的 WSL1 环境明确显示不支持。

引导中的 `sudo` 命令需要管理员权限，**只复制，不执行**。加入 docker 组意味着接近 root 的权限；
授权后需重新登录并启动 AC-Prof，`newgrp` 不能改变已运行进程的用户组。
不自动删除安装、覆盖 Docker 软件源、切换 Context 或改变用户配置。
软件源命令遇到已有源或密钥时停止，由用户按官方文档核对；不使用远程安装脚本或强制卸载。

安装完成或服务修复后，点击“重新检查”即可在当前 AC-Prof 中更新结果；不需要重启。
检测遵守 `DOCKER_CONTEXT` 优先于 `DOCKER_HOST` 的选择，不探测不符合本机要求的远程端点。
若修复涉及改变启动环境变量，父 shell 的后续变更不会传入已运行的 AC-Prof：需从修正后的 shell 重新启动。
PATH 中没有标准系统目录可供链接时，也会明确给出重新启动说明。
检查中保留上次诊断并标注其时效；失败保留具体原因及下一步，正式测量期间禁止重新检查。

安装来源：[Ubuntu](https://docs.docker.com/engine/install/ubuntu/)、
[Debian](https://docs.docker.com/engine/install/debian/)、[其他 Linux](https://docs.docker.com/engine/install/)、
[Socket 与用户组](https://docs.docker.com/engine/install/linux-postinstall/)。

### 环境检查的证据范围

检查通过仅说明所列环境检查通过，不代表实际模型推理或完整 Profiler 运行已经通过。
例如 cgroup 读数来自当前进程所在的本机 cgroup；Profiler `--version` 只证明工具可执行。
Torch Profiler 会执行一个 4×4 CPU 矩阵乘法并验证算子事件与 FLOPs；Massif 会跟踪一个
64 KiB 堆分配，验证生成的报告含快照和有效堆读数。两项都自动检查，无需勾选 Profiler。
优先使用本地依赖环境镜像；依赖层已清理时尝试保留的派生镜像。每项找到首个可用 Runtime
即停止，说明区保留镜像 ID、结果与此前失败原因，不将该结果推广到其他 Runtime 或 GPU。
没有本地镜像、工具缺失或候选均失败时，无论是否勾选分析器，都显示警告并保留原因；只有时间预算耗尽且仍有候选未检查时显示
待验证状态，说明区显示具体原因。每个容器最多 15 秒、每项尝试预算 30 秒，容器清理另有独立时限。
检查容器禁用网络、使用只读根目录和临时目录，限制 CPU、内存及进程数，禁止拉取镜像；
完成、失败或超时后按不可变容器 ID 清理。无法确认清理完成时，停止后续检查并阻止启动。
基础延迟、吞吐属于实际实验结果，不列为机器环境检查项。环境检查不下载、不构建、不加载模型；
正式实验仍在准备阶段校验选定 Runtime、设备和模型的执行能力。

修改 Runtime、模式、GPU 或 Profiler 后，基于保留的整机证据重新评估适用范围；
失效的实验预检立即转为待检查，重检期间不计入旧成功或旧错误。悬停和切换语言只读取缓存。
`F6`、`/check` 和「重新检查」刷新同一份全机结果，重复请求不会启动并行检查。
检查持有既有测量锁，与正式采集和补采互斥；测量中保留缓存并禁用重检。

实验启动另行保留原有配置校验与错误提示：缺少可选机器能力不会因此阻止无关的 Basic 实验；
Full 必需能力仍会阻断，绝不自动降级。相关实验参数变化后自动刷新该配置的前置校验，
迟到结果不覆盖编辑中的表单。`F5`、`/run` 和确认后的启动继续执行原有校验。

### 自动配置检查

编辑时先复用表单校验显示对应字段的错误，不弹窗、不跳页、不移动焦点；模型 ID 为空或参数
不合法时禁用“开始采集”，暂停由配置变更触发的环境预检。修正后自动继续。

| 变更 | 自动处理 |
| --- | --- |
| Runtime、GPU、Profiling 模式、Profiler、CPU 亲和性、抓包网卡 | 停止修改约 500ms 后执行当前配置的必要预检 |
| Process CPU／内存配额，包括 Auto 已解析为 Process | 重新验证资源限制 |
| Warmup、Repeat、窗口请求数、Docker 数值配额及其他 workload 参数 | 校验表单，刷新命令和采集计划，复用已有环境证据 |

连续编辑合并执行。检查期间可继续输入、滚动和切换页面；已有检查结束后只检查最新配置，
过期结果不会将新配置标为就绪。相同环境配置不重复扫描，失败或超时保留具体原因；
用 `F6`、`/check` 或「重新检查」可主动重试并刷新外部环境变化。
若整机自检报告容器清理尚未确认，修改配置不能绕过该失败；处理清理问题后需手动重新检查。

采集计划下方显示「配置待完善 / 待检查 / 检查中 / 已就绪 / 受限 / 失败」。
受限表示必要预检已通过，但存在能力或数据质量警告；失败阻止启动。采集计划中的正式窗口不足提示
也计入全局警告，可定位到窗口数配置；它不阻止 Smoke 流程验证，不触发环境探测。

启动时及手动检查仍刷新全部机器能力；配置自动检查只复用 `quick_preflight()` 检查所需条件，
全局状态按当前请求重新分类，整机证据及其检查时间保留最近一次完整扫描结果。自动检查不下载模型、不构建镜像，
不启动正式采集。准备、采集、补采和清理占用期间暂停待检请求；任务结束后继续，退出时停止
定时器并丢弃迟到回调。所有环境探测继续持有既有测量锁，避免干扰其他 AC-Prof 进程。

实现沿用 [Textual Worker 的线程回调与取消检查](https://github.com/Textualize/textual/blob/v8.2.8/docs/examples/guide/workers/weather05.py)，
采用单个 Worker 与最新配置快照，避免取消线程后立即启动重叠探测。
状态反馈参考 [Carbon Inline loading](https://carbondesignsystem.com/components/inline-loading/usage/)，
使用原位置状态和字段错误，保留输入与操作上下文，不新增 UI 框架或依赖。

## 输入与确认

`acprof tui` 在 VS Code 集成终端（`TERM_PROGRAM=vscode`）默认采用 Unicode 11 字宽，
使 `☰` 与该终端的默认规则一致占 1 格。Windows Terminal（包括 PowerShell 与 WSL Ubuntu
标签页）沿用 Rich 默认字宽：其 Unicode 16 字宽表将 `☰` 计为 2 格，强制降为 Unicode 11
会使同一行右侧表单和边框向右错位。`WT_SESSION` 本身不能说明终端使用的 Unicode 版本。
显式设置的 `UNICODE_VERSION` 优先；只有确认客户端采用旧字宽规则时，才使用
`UNICODE_VERSION=11.0.0 acprof tui`，SSH 会话同样以客户端终端为准。
此兼容处理在首次加载 Textual 前执行，复用 Rich 的
[`UNICODE_VERSION` 支持](https://github.com/Textualize/rich/blob/v15.0.0/rich/_unicode_data/__init__.py)
及 VS Code 的 [Unicode 11 默认配置](https://github.com/microsoft/vscode/blob/f38b6d8928a171c65a42174e8394270760203fac/src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts)；
Windows Terminal 的字宽依据其 [CodepointWidthDetector](https://github.com/microsoft/terminal/blob/3b8c5606ee1866e7bf5c4e84e962798492282097/src/types/CodepointWidthDetector.cpp)。
无新增依赖、轮询或第三方库补丁。

表单输入框、选择框及其展开菜单默认使用 `solid` 细线边框，普通、聚焦和禁用状态保持同一种线框。
这减少了对终端拼接 `tall` 块状字符的依赖，无需额外设置。终端仍需支持 UTF-8、中文字体和
基础 Unicode 线框；`--color-system` 只调整颜色深度，不改变字体或边框字符，也不提供纯 ASCII 界面。
底色统一透明，随所在页面的背景变化；悬停、聚焦时也不叠加底色，聚焦通过青色边框提示。
输入文字的选区和展开菜单的当前选项仍保留高亮，便于编辑和选择。

所有输入框均支持 `Ctrl+A` 全选当前框内的文本；全选后键入或粘贴会替换全文，
按 `Backspace` 或 `Delete` 清空。`Home` 仍移到行首，`Ctrl+Shift+A` 也可全选。
输入框使用细竖线插入光标，停下输入后亮 0.5 秒、灭 0.5 秒；键入、移动或点击后立即显示。
TUI 直接控制光标亮灭，不依赖终端的闪烁设置，也不为闪烁重绘界面。离开输入框后隐藏并停止
计时，正式测量窗口内暂停闪烁。光标形状需要终端支持 DECSCUSR；退出或挂起 TUI 时重置样式。

操作按钮统一使用透明底色和细线圆角边框，颜色含义不随主题变化：青色表示当前选择或主要操作，
普通白色表示一般操作，黄色表示补采等有风险但可恢复的操作，红色表示删除或终止，灰色表示禁用，
绿色表示成功或服务就绪。浅色主题用深色普通文字及较深的同色系操作颜色保持可读性。
悬停或键盘聚焦时加粗并加下划线，保留操作本身的颜色；禁用时统一变灰。
日志工具栏和确认弹窗也使用相同语义，删除、终止的确认按钮保持红色，补采确认保持黄色。
确认弹窗打开时不预选按钮；使用鼠标时，移入按钮才高亮，移出后恢复。
键盘操作使用 `Tab` / `Shift+Tab` 选择按钮，`Enter` 执行所选操作，`Esc` 取消；未选择时直接按 `Enter` 不执行操作。

操作通知显示在右下角，可点击关闭。通知覆盖按钮、切换窗口尺寸或隐藏快捷命令栏时，
中文提示应保持完整；这项显示修复同时适用于 VS Code、Antigravity 和其他终端。

### 模型契约解析与验证

填写实验参数后点击“开始采集”，系统在同一次子进程中完成模型解析、接口检查、环境与模型准备、
最小输入验证，成功后直接进入正式采集。首页保留“高级参数”“探测最大输入”“开始采集”；
无需先执行独立的模型诊断。

点击开始立即打开“正在检测模型”。同一弹窗显示真实阶段：读取模型信息、确认模型接口、
准备运行环境、准备模型、验证模型运行；不使用模拟百分比。准备期间不能修改实验配置。
点击“取消”会终止准备子进程，由其清理所拥有的容器、临时 Source Bundle 和测量锁；
清理完成后返回配置页。强制终止留下的容器按[容器清理规则](../profiling/lifecycle.md#容器清理与失败证据)处理。

只有真正的未决项或冲突才打开“模型确认”。已确定的 Model、Revision、Task、Backend、Adapter / Interface
以只读文本显示；有合法候选的字段使用 Select，本地声明使用路径输入，复杂输入映射使用 JSON。
“应用字段”将答案交给 resolver 重新解析，所有必填字段 resolved 后才能点击“确定”。
可修改的自动选择放在折叠的“高级修改”，原始契约、来源与内部身份放在“高级详情”；没有详情时不显示该折叠区。
修改会重新解析，不能直接改写最终 contract 或把未决状态标为成功。

选择优先级为显式配置、同一证据对应的已确认选择、自动推断、询问用户。
决策缓存位于输出根目录的 `.model-contracts/decisions/`，按模型 SHA、静态证据及显式配置隔离；
它不缓存运行验证成功。网络、权限与文件错误显示原因和处理建议，不能作为可忽略的适配选项。
单段模型 ID（如 `gpt2`）合法，连接失败不等于模型不存在。

CPU + GPU 配置分别执行一次最小输入验证，两者完整通过后显示“✓ 模型检测完成”，
自动关闭弹窗并继续采集，无需再次确认。如果终止确认或其他弹窗仍在上方，保留其选择和焦点；
关闭上方弹窗后直接回到运行页面，不再显示已结束的模型检测。失败时原弹窗显示失败阶段、原因和处理建议，
详细信息默认展开，使用与监控页一致的只读日志视图，支持滚动、选中文字、`Ctrl+A` 全选和 `Ctrl+C` 复制；原始容器输出另存日志。
底部固定显示“返回配置”和“重试”；镜像准备或运行验证失败时还显示“重新准备环境”，长详情不会把按钮挤出弹窗。
悬停按钮可查看实际操作：“返回配置”先打开终止确认，确认后停止任务并清理资源、保留已写入的结果；
“重试”以当前配置重试失败阶段，按原有规则复用模型、环境和输入；“重新准备环境”重新准备环境和输入，再验证模型，Docker 重建仍可使用构建缓存。
失败运行验证的报告与日志保存在 `runtime-attempts/`，不覆盖历史失败证据。

续跑仍遵循冻结实验身份检查，并且只能复用成功的运行验证记录；没有成功记录的旧实验需新建目录。
静态解析、接口检查、运行验证与正式测量的范围见[运行兼容](../models/contracts.md#自动生成模型契约m1m6)。

## 界面偏好

“应用设置”页按功能分成三个带标题的区块：

- **界面与交互**：界面语言、界面主题、底部快捷命令框。
- **日志**：保留日志行数、日志自动换行。
- **连接与权限**：说明连接与采集权限的用途，提供“管理连接与权限”入口。

区块按上述顺序纵向排列；窗口较小时可滚动，底部“恢复界面默认”和“保存设置”始终可见。
“管理连接与权限”入口可填写 Hugging Face Token 和企业微信 Webhook。网络统一使用系统网络环境，界面不配置 VPN／代理或选择 HF 下载模式。
敏感字段默认遮蔽；底部操作栏中“关闭弹窗”右侧的“显示敏感字段”可切换遮蔽状态，滚动表单时仍可操作。
点击右下角“保存配置”后写入 `.env.local` 并更新当前会话，新任务直接使用保存值。
关闭不保存。原文件保留为 `.env.local.bak`；完整优先级、备份和冲突处理见
[TUI 本地设置](configuration.md#tui-本地设置)。

同一窗口的“采集权限”页可检查主机条件并配置 perf / tcpdump。两个选项可独立勾选，也可同时选中，默认均选中；
复选框选中显示 `✓`，未选中显示空框；禁用状态及 `NO_COLOR` 灰度显示下也保留这一区别。
点击选项或聚焦后按空格切换。先预览操作，再在系统终端完成
sudo 授权；完成或取消后返回 TUI。配置会留存原权限，随后自动复查；它不会启动模型或发送通知。
权限操作预览在终端中居中显示；命令列表过长时可滚动，底部操作按钮保持可见。
依赖与权限范围见[最小权限安装](../getting_started/installation.md#最小权限安装)。运行采集、检查或其他任务时无法编辑这些配置。

设置页同时保留界面偏好：界面语言（简体中文 / English）、八种主题（深海蓝、纸白、石墨灰、松林绿、暮紫、琥珀、暖砂、雾蓝）、
日志保留行数（500 / 1000 / 3000 / 10000）、日志自动换行，以及是否显示底部快捷命令框。
快捷命令框默认不显示；已有设置缺少此字段时也默认隐藏，明确保存的开关值继续沿用。
默认主题在下拉列表及选中框中标注为“石墨灰 · 深色（默认）”。
修改当次生效，点击“保存设置”后，下次启动沿用。
按 `F2` 打开设置，在“界面语言 / Language”选择 `English` 即可切换为英文；
页面、表单、提示、确认弹窗和监控状态同步切换，当前输入、预设、日志选区和已加载概览及状态保留。
日志中的原始子进程输出保留原文，模型 ID、路径、命令和实验数据不做翻译。
默认使用简体中文；已有设置文件缺少语言字段时也使用简体中文。
换行设置会重新排布已有日志；行数上限按原始文本行计算，调整后立即裁剪较旧内容。
“恢复界面默认”先恢复当次显示，再点击保存即可保留。
