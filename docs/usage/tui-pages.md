# TUI 页面与功能

[← 返回专题目录](tui.md)

## 启动和页面

首次 clone 可以运行 `./setup.sh`，完成安装和 basic 环境检查后自动进入入门配置。
通过此脚本或其他[发行包方式](../development/distribution.md)安装后，统一使用 `acprof tui` 启动全屏 TUI：

```bash
acprof tui
```

也可以预填模型并直接加载最小 smoke 配置：

```bash
acprof tui --model google-bert/bert-base-uncased --preset smoke
```

首次打开且没有保存实验配置时使用 Smoke：`basic`、CPU、1 核、4 GB、无 warmup、单次请求，
Idle 与 cooldown 为 0，关闭独立 profiler，初始通知为 `none`。保存过的配置和主动选择的主矩阵继续生效。
高级参数中的“深度性能分析”提供 PyTorch Profiler、NVIDIA NCU、Valgrind Massif、
NVIDIA Nsys 四个独立勾选项；可单选或任意组合，默认均关闭。配置保存和命令预览继续使用
`compute_profile_tool`（Torch / NCU）与 `execution_profile_tool`（Massif / Nsys）
的原有 `none` / 单工具 / `both` 取值，不改变采集窗口、已有配置或实验结果格式。
这些分析器分别运行且可能增加准备时间；能否执行仍由当前资源模式和环境检查决定。
Smoke 的 `--input-scale-policy minimal` 在任务解析后从现有 workload 选择最小单一尺度：例如普通文本
64 tokens、语音 1 s、图像边长倍率 0.1。随后仍执行原有模型约束检查，不保证任意模型都能在 4 GB 内运行。
用户主动填写 `--input-scales` 时严格验证该值，不用 Smoke 默认值覆盖或截短。输入框在解析前标明单位待解析，
输入计划完成后显示实际单位和尺度。需要完整采集时在“高级参数”中改为 `full`；主矩阵预设为 `full`。
原先相同的“完整默认”选项已合并到“主矩阵”；CLI 使用 `--preset main`，快捷命令使用 `/main`。
两种模式的主机条件和指标范围见[采集协议](../profiling/measurement.md#profiling-mode-与能力证据)。

预设匹配只比较实验参数。输出目录、下载策略、缓存、通知、恢复和镜像复用设置不会改变预设身份；
修改 CPU、输入规模、重复次数等参数后显示“预设名 · 已调整”，恢复原参数后恢复原标签。
切换预设只修改实验参数，保留下载预算、下载源、Model Store 路径与容量、输出目录、模型声明和通知选择。
续跑时不允许切换到不同实验参数；请取消续跑并选择新的输出目录。后端仍核对完整恢复身份，不混用旧计划。
启动确认显示预算和缓存位置；传输权重前的下载确认显示预计下载量、有效预算和实际 Model Store 路径。

`--output-dir` 覆盖预设或已保存配置中的输出目录，例如
`acprof tui --model google-bert/bert-base-uncased --preset smoke --output-dir results/my-first-run`。
启动参数只预填本次界面，打开或退出界面不会覆盖已保存的实验默认值；不传参数时恢复保存的设置，未保存时用 Smoke。
`setup.sh` 每次使用新的结果目录，直接运行 smoke 时默认仍为 `results/smoke`，重做实验需更换目录。

默认以 RGB 真彩色显示，默认主题为“石墨灰 · 深色”，普通终端和 VS Code 使用相同配色；SSH 未传递 `COLORTERM`
也不会自动降级。仅支持 256 色的终端可加 `--color-system 256`，需要环境自动检测时使用
`--color-system auto`；具体行为见[终端颜色说明](configuration.md#tui-终端颜色)。

TUI 分为“实验配置”“运行监控”“绘图工具”“统计报告”“补采工具”“镜像管理”和“应用设置”七页。
“应用设置”固定在顶部导航栏最右侧，其余页面靠左排列；中英文切换和终端缩放后保持这一布局。
页面统一为顶部导航、页面标题或状态摘要、主内容、底部操作栏；主内容滚动时，摘要和操作栏保持可见。
底栏左侧集中放置导航和次要动作（如高级参数、读取摘要、查看补采计划、日志工具），
右侧放置本页主操作。按钮随中英文标签调整宽度，缩窄终端后仍按左右分组排列。
绘图摘要和统计表格采用无外框内容区，仅保留一条分隔线；输入框和操作按钮仍保留焦点边框。
“开始采集”“生成图表”“计算统计”“执行补采”“删除所选”“保存设置”固定在各页右下角，
监控页的日志工具和“终止任务”位于底栏，放大日志后仍可操作。可选的快捷命令框位于页面操作栏下方。
实验页集中填写模型、资源矩阵和输入规模，提供 Smoke、主矩阵及自定义选项和自动命令预览；底栏提供最大输入探测。
每次启动自动在后台检查环境；仅有警告或错误时，页头才出现环境状态入口。
主要操作上方显示配置数、输入档数、预热与正式窗口数、时间量级及下载预算。自动范围尚未规划时显示“待解析”；
完成准备阶段的输入规划后更新实际档位，不读取正在写入的 CSV。时间按自动窗口目标或每请求 1 s 的明确假设估计，
完整模式计入配置的 Idle 与 cooldown；不包含下载、镜像构建、服务启动、校准或独立 profiler。
这些是规模提示，不是实测耗时或超时保证；悬停摘要和开始确认可查看假设、缓存与来源详情，高级参数继续折叠。
概要另显示每条件计划的正式窗口数：少于 3 个时提示仅验证流程、没有置信区间；
至少 3 个时仍说明有效数以结果为准，不视作证据充分。修改 revision 会立即使旧输入计划、
单位和档位概要失效，待新版本规划完成后更新；单独修改 Repeat 保留已解析档位并重算总窗口。
提交无效配置时，界面切到首个错误字段所在页面，展开对应分组并滚动、聚焦到输入框。
每个无效字段旁持续显示具体原因；修正后自动清除，切换语言仍保留当前错误。字段身份来自共享的
`RunConfigError.issues`，例如 `cpus`、`repeat`、`max_download`，不依赖错误文案或语言匹配。
表单会随终端宽度切换排列。监控页显示 case 级进度和日志；绘图页通过结果 CSV 读取摘要、生成图表，
补采页通过结果目录选择 profiler、查看补采计划或执行补采。绘图和补采任务启动后切换到监控页查看日志。
`/results`、`/summary` 读取摘要后打开绘图页。开始探测、采集和执行补采前都会显示确认页。

按钮、快捷键和快捷命令使用同一套任务状态。环境检查、统计、补采、资源清理期间不能再启动采集；
“终止任务”只在存在仍在运行的受控子进程时可用；退出后的产物核验继续锁定采集入口，但不再提供终止操作。
摘要、报告读取期间可以切换路径、重新读取或退出，
迟到结果不会覆盖新选择。`/cancel` 可取消当前结果读取；后台读取实际结束前仍禁止启动采集。

### 从本地记录选择模型

模型 ID 输入框继续支持自由输入；旁边“模型候选”按钮或输入框内的 `F4` 打开搜索，选择后仍回填同一个输入框。
候选来自已知实验根目录、coverage attempts 和当前 Model Store。列表显示当前条件成功记录、已缓存待验证、
授权限制、历史资源不足或需要重新验证，详情保留原实验、失败原因和当时资源；可以直接打开原结果或 coverage 报告。
缓存命中不代表推理成功。成功状态只覆盖记录中最小输入的 predict/postprocess 验证，不承诺完整矩阵、质量或 profiler 成功；
正式准备仍重新执行既有校验，候选不会绕过这些检查。

状态绑定固定 revision、runtime profile 与依赖锁、主机、设备 UUID、CPU/内存/批量、CPU 绑定、线程环境、
输入尺度与规划策略、声明文件、超时和采集源码。条件变更或历史证据不足显示需要重新验证，并保留旧授权或资源失败标签。
coverage 记录尚缺完整 runtime environment 与当前条件核验，因此显示需要重新验证，同时保留原失败标签和 attempt 资源。
选择候选会把 commit SHA 填入高级参数中的 revision；主动换成其他自由文本模型时清除候选自动填入的 SHA，
用户自行更改过的 revision 保留。未填写 revision 时，候选以自身记录的固定 SHA 展示条件，选择后固定该 SHA。

每次打开在空闲 worker 中重新读取；Model Store 只核对受限元数据和文件命中，不计算全部权重哈希、不下载、不等待 GC 锁。
需要根据 driver 选择 Torch 平台时整批只进行一次有界探测；GPU 任务另做一次有界 UUID 查询。
关闭会取消后续读取，已经开始的有界查询结束后才释放采集入口。选过一次候选后，原输入框也提供本地模型名前缀补全。
没有本地候选时提示可直接输入 Hugging Face 模型 ID；已有候选但搜索不匹配时提示修改搜索词。
加载期间保持读取提示，读取异常或扫描上限导致没有记录时保留诊断提示，不将它们显示为没有历史记录。

### 查找实验与恢复参数

绘图、统计、左右比较组和补采的路径框旁均有“选择实验”。选择器按模型、日期、设备、状态或 Run ID 搜索，
可选入路径、查看结果、复用配置或检查“恢复 / 重试”；准备阶段失败、尚无 CSV 的记录仍能查看原失败证据。
日期按运行 TUI 的机器本地时区显示为 `YYYY-MM-DD HH:MM:SS`，搜索同时支持显示日期和原始时间戳。
缺失或无效的日期保持原样；产物中的时间戳不变。
设备列优先显示实验记录中的显卡型号；悬停设备单元格可查看完整 GPU UUID，搜索支持型号和 UUID。
历史记录缺少型号时保留原设备标识；底层记录和设备匹配仍使用原 UUID。
损坏清单、未知布局和不安全的产物路径会按目录显示警告，并继续列出其他正常实验；
该目录不能据此恢复，也不会被当作旧布局读取。JSON 读取统一限制为 4 MiB，并拒绝非有限数值。
索引每次打开均从原始产物重建，只读取项目 `results`、当前输出目录及已有结果输入路径，搜索范围显示在弹窗内。
搜索范围在后台检查目录是否存在：项目内使用相对路径，父子目录在摘要中合并；悬停可查看完整路径及被跳过的失效路径或检查错误。
摘要合并不删除显式子目录的扫描入口，因此较深目录或已有实验目录内明确指定的记录仍可读取。
历史结果路径保留在设置中，目录暂时不可用时只跳过本次展示，不自动清空记忆或创建目录。模型候选的 Model Store 路径使用同样的显示规则。
需要查找其他位置时先在路径框填入该已知结果根目录。目录枚举、深度、JSON 大小与重复 CSV 核验均有上限，
到达上限会显示原因；关闭会取消读取，后台线程实际结束后才释放采集入口。
产物 JSON 中的非有限数值（包括 `NaN`、`Infinity` 和溢出指数）视为损坏证据：选择器显示读取警告，
不使用该文件恢复冻结参数，也不把这些值转成可搜索的状态或模型信息。

实验身份来自 `run_state.run_id`；移动目录保持身份，相同 Run ID 的副本合并为多个路径，内容冲突或证据预算不足会
明确标记并禁止续跑。历史缺失 Run ID 继续为未知，不用目录名代替身份。“复用配置”保留已冻结的公共参数，
包括界面未展示的 matrix order、seed、SLO 和 profiler 参数，并固定已有 commit SHA，分配新的输出位置。
这些参数也随保存设置和命令预览保留；表单编辑只覆盖对应字段，特殊参数使 Smoke/主矩阵显示为自定义或已调整。
开始后由后端生成新的 Run ID。额外参数只能是当前公共 CLI 支持且未在表单显式映射的选项，不能覆盖模型、输出路径或恢复开关。

点击“开始采集”遇到旧实验目录，或在运行失败后点击监控页的“恢复 / 重试”，均进入同一个恢复检查页；
不必先到高级参数猜测恢复开关，也不必手动删除日志或更改路径。检查页在后台核对原参数、采集源码、
Python 依赖、主机身份、冻结产物和已完成 case；有活动 writer、证据缺失或身份变化时禁用续跑并说明原因。

- 准备尚未完成且条件一致：显示“重试准备”，使用原参数，并先归档上一次准备的日志和状态。
- 已冻结运行环境：显示“继续实验”，通过 `run --resume` 保留已完成 case，按原协议处理中断 case。
- 无法续跑或希望重测：点击“新建实验”，使用当前配置自动分配 `experiment-<UUID>` 输出根目录；
  从历史选择器进入时，当前配置来自原实验的完整冻结参数。原目录与历史产物均保留。

“命令详情”可检查两个动作的完整命令；取消不会修改表单或实验产物。确认后再次读取原记录和恢复条件，
需要更换采集模式时先重新检查相应环境；预检期间编辑配置会取消待启动动作。实际 runner 仍核对镜像和硬件，
界面检查通过不等于实际推理已经验证。检查期间禁止启动采集，取消或关闭后的过期结果不会触发启动。
若最内层模型目录被改名，续跑要求恢复原模型目录名；移动其父目录不受此限制。
已完成、缺失冻结配置、身份冲突的记录不提供续跑。所有检查与目录操作发生在正式测量窗口之外。

### 实验结束与结果摘要

最终状态分为“已完成”“部分完成”“已停止”“失败”和“清理未完成”。日志报告完成后先显示“核验产物”；退出码 0 本身不能证明实验完成。
采集或探测在预检时发现不支持的任务，会保留“任务不支持”状态、具体原因和处理办法。
TUI 关联当前子进程与 `run_state` 中新增的 attempt，再通过既有产物布局、计划覆盖审计及能力报告核对完成范围。
能力报告按有界 JSON 对象读取；文件超限、格式损坏或包含非有限数值时，保留已归属的 CSV 与 case 证据，
将状态降为“部分完成”并显示原因，不把损坏报告当作完整画像。
主运行状态同样按 4 MiB 上限读取并拒绝非有限数值；若子进程结束后 `run_state.json` 损坏，
TUI 会显示未核验 CSV 的位置，但没有 PID 与新增 attempt 证据时不会把它自动归属为本次结果。
停止后保留已写入的 case，监控详情显示保留目录及续跑提示。进程未确认退出时继续保留所有权、禁用新的采集，
可再次请求停止。

目标目录中已有 CSV 不代表本次生成结果。预检失败或没有本次产物时显示“本次未产生结果”，
历史结果仍可通过原路径读取；恢复一个已完成实验会说明本次未重新采集。

摘要在后台读取，按现有窗口统计的 CPU、内存上限、GPU、输入规模和环境分组，展示可用的延迟、吞吐量、
内存及能耗窗口均值。只统计 `status=ok`、`warmup=0`，不计算跨配置的总体平均或“最快配置”。
窗口不足时明确标记；摘要不执行 bootstrap，置信区间需主动计算统计报告。
摘要最多展示前 30 个配置，更多配置请用统计报告；缺少配置身份字段的历史 CSV 只显示行数及缺失原因。
读取失败保留可操作界面。所有读取和统计都位于正式测量窗口之外。

### 数值状态

| 显示 | 含义 |
| --- | --- |
| `—` | 不适用，例如尚未开始任务的运行时间、CPU 实验中的 GPU 能耗 |
| `…` | 正在计算或读取，完成或失败后更新为结果或错误说明 |
| `未知` | 无法确定，例如无法核验的镜像大小、缺失的数据或样本不足的统计区间 |

真实的零仍显示为 `0` 或带单位的零。未知数值不附加单位；英文界面将 `未知` 显示为 `Unknown`。
统计表的说明和镜像诊断保留缺失原因；进度日志、CSV 和报告 JSON 的原始值不受显示规则影响。

## 统计报告

“统计报告”页可查看窗口置信区间、独立实验比较、CPU/GPU 监测开销和 CLI/TUI 对照：

- 采集结束后，统计路径会自动带入结果 CSV（保留已手动编辑的路径）；确认路径后点击“计算统计”，也可输入其他实验目录或 CSV。
  计算调用 `acprof stats`，新报告保存到 v2 结果目录的 `plots/analysis/window-statistics-YYYYMMDD-HHMMSS-ffffff.json`（旧目录继续使用 `analysis/`），使用本地日期、时间和六位微秒。
  保存前比较该目录已有 JSON 的完整内容；相同则提示“已有相同报告”及路径，并直接显示已有报告，不新增文件。旧 UUID 文件名也参与比较，JSON 缩进或字段顺序不影响判断。
  源 CSV、统计参数或统计结果不同会保存新报告；旧报告保留，时间戳重名时递增微秒避免覆盖。
- 查看已生成的报告时，输入 JSON 路径后点击“查看报告”。表格支持方向键、滚动和选行查看口径；延迟以 ms 显示。
- `/stats [csv/dir]` 计算统计，`/report [json]` 打开报告。计算需要空闲；读取期间可以选择另一份报告，原始 CSV 与旧报告保留。

展开“独立实验比较”，分别填写左右实验目录或结果 CSV；每组多个独立实验用分号分隔，路径中的分号可用双引号保护。
选择基线与“相同硬件 / 跨硬件 / 资源配置扩展”用途后点击“比较实验”。
资源配置扩展时显示左右 CPU/内存坐标与允许变化的维度；其余线程、设备、输入输出等条件仍由比较后端严格判断。该操作调用已有 `acprof compare`，所选基线作为报告左组，
结果保存到基线首个实验的 `plots/analysis/experiment-comparison-<UTC时间>.json`（旧目录使用 `analysis/`），随后自动打开。
也可直接查看 CLI 生成的 `independent_experiment_comparison` JSON；展示均值、变化比例、差值、差值与比值区间、独立实验数。
不可比、条件未知或重复不足时先显示原因；即使 CLI 因不可比返回非零码，已生成报告仍可查看。
选行详情保留质量检查、来源、运行与测量状态、条件检查和原报告限制。表格横向滚动查看全部列，详情区可滚动。
比较与报告读取继续受任务限制保护，正式测量时不能启动。coverage schema 2 续跑报告也可读取，详情保留 attempt 及原失败证据。

窗口统计需要主动点击，不会在每次采集后自动计算；监测开销及 CLI/TUI 对照仍由独立工具运行，
本页读取它们已经生成的报告。统计口径、默认指标与样本不足的说明见[指标分析](../results/comparisons.md#窗口置信区间与开销对照)。

## 表格列宽

所有 TUI 表格（统计报告、镜像树、镜像列表、层共享）均支持按住表头相邻列之间的 `│` 左右拖动，手动调整左侧列宽；最后一列右侧不显示拖动手柄。
表头与单元格内容统一左对齐，镜像树名称保留层级缩进；拖动改宽后保持对齐。
空表格的表头横条和已有表头右侧的留白不触发选择或排序；行尾留白仍可定位到对应行。
松开鼠标结束；拖动不触发排序、勾选或折叠。一般列最窄保留一个字符格，镜像树名称列另保留层级箭头与勾选空间。
手动列宽在本次会话的排序、筛选、刷新、视图与语言切换、终端缩放后保留，重启 TUI 后恢复默认；任务运行期间暂停拖动。

## 镜像管理

“镜像管理”页（`/images`）默认打开可折叠的**镜像树**，可切换到**镜像列表**或**层共享**。
首次打开时仅显示顶层镜像，各分支默认折叠；按需逐级展开，刷新时保留已有展开状态，新出现的分支默认折叠。
视图切换按钮同一行、“层共享”右侧的“存储空间”打开独立弹窗，显示 Docker 数据目录、所在磁盘的容量与使用率、镜像／容器／Volume／Build Cache 的占用与可回收量，以及当前勾选镜像的释放估算和删除后可用空间。
打开弹窗时读取一次，点击“刷新”重新查询；“关闭 (Esc)”或 `Esc` 返回镜像页并保留勾选。小窗口中内容可滚动，底部按钮固定可见。
数值使用 GiB，较小数据用 MiB、KiB 或 B；无法核验的值显示“未知”。释放量仅是按共享层去重后的估算上限，缓存可能继续占用数据；弹窗不执行删除或清理。
磁盘“可用”不含文件系统预留块，远程或虚拟机 Docker 无法核验本机磁盘时显示未知。查询期间禁止启动采集；即使关闭弹窗，仍等后台查询结束后恢复启动入口。
打开页面自动读取清单，空闲时每轮读取完成后 5 秒更新；刷新保留有效勾选、筛选、折叠和浏览位置。
树中显示逻辑名称、完整大小与相对父镜像的新增大小；搜索支持包名和版本，并保留祖先路径。默认“AC-Prof 镜像”范围仅补齐 AC-Prof 管理的祖先，不把第三方上游镜像显示为额外根节点；选择“全部镜像”可查看包括上游 Python 基础镜像在内的完整本地依赖树。隐藏节点不改变真实继承、镜像详情、勾选和删除时的安全核验。
平台节点统一显示 `Python CPU`、`PyTorch CPU`、`PyTorch CUDA 12.4`、`PyTorch CUDA 12.8`，同平台子节点省略重复后缀；依赖版本号保留小数点。完整镜像视图中，无标签第三方镜像若仓库 digest 与项目锁定的 Python Slim 上游镜像一致，显示 `Python 3.10 Slim（上游基础）`（版本从锁定引用读取）；无法核验的镜像保留短 ID。镜像的原始 ID 和仓库摘要仍在诊断信息中可查看，不修改 Docker 标签。
`←/→` 或树的箭头折叠/展开；树和列表中，点击 `□ / ☑ / ◩` 及左右各一格留白勾选/取消，点击行内其他位置只查看详情。
勾选上层会同时选中自身及全部下层，包括折叠和筛选隐藏的镜像；状态栏显示筛选外的已选数量。
只选下层不会自动选择上层。取消任一下层会取消其上层的删除选择；`◩` 表示仅下层有选择，本镜像保留。
再次勾选半选节点会补齐可选分支；可选下层已经全部选中时，再次操作会清空该分支。
存在容器引用时，保留被引用镜像及其上层，仍可选择其它分支；页面显示原因。
镜像树左侧会高亮通往当前行的祖先连接线，随鼠标点击或方向键移动更新。
空格可切换当前分支的勾选状态；列表表头可排序。镜像列表只固定最左侧勾选列，“环境 / 模型”与大小、`Repository`、`Tag` 等数据列一起横向滚动。
详情先显示镜像摘要（名称、类型、大小、容器引用数与删除释放估算），右上角显示 Docker 镜像的创建日期（按本机时区转换至分钟；缺失或无效时显示“未知”），下方“依赖清单”“镜像信息”“诊断信息”默认折叠。镜像信息中仍保留 Docker 原始创建时间；层共享详情不显示镜像创建日期。
按住列表与详情之间的“↕ 拖动调整详情高度”分隔条上下拖动：向上扩大详情，向下扩大列表。
拖动分隔条不选择文字，也不触发镜像树、镜像列表或层共享视图的自动滚动；列表位于顶部时保持在顶部。
分隔条可用 `Tab` 聚焦，`↑/↓` 微调、`Home` 恢复默认高度；高度在本次会话保留，缩小终端时自动限制，放大后恢复。两侧内容仍可独立滚动。
点击分组标题，或用 `Tab` 聚焦后按 `Enter` 展开；依赖标题显示包数量、“无新增包”或“未知”，展开后逐行查看完整包版本。
“镜像信息”显示继承路径、共享/独有空间、模型、标签与容器；完整 SHA、依赖来源、history 核验和空间计算说明放在“诊断信息”。
切换语言、缩放窗口或勾选同一镜像时保留展开状态；换一个镜像时回到折叠摘要。依赖按镜像身份匹配锁，运行依赖层扣除平台已有包；层共享视图也将引用镜像与诊断标识分组。
“选择同模型”会选中该模型可删除的服务、权重和调试镜像，保留公共依赖及仍有未选下层的上层镜像。
点击“删除所选”后，核对全部镜像 ID、标签、筛选外数量及 `≈` 推断关系并确认。删除从下层向上执行，
下层被占用、删除失败或仍然存在时保留其上层，其它独立分支可继续处理。
确认框显示“预计可释放：约 X”，悬停旁边的 `ℹ` 可查看“实际释放空间可能受共享镜像层和构建缓存影响，以清理后核验为准。”
已有容器引用的镜像不能删除；仍需续采或补采时应保留原实验镜像。页面按 image ID 合并别名，大小包含共享层，
释放估算按所选集合去重，构建缓存仍可能保留数据；`?` 表示未知。
离开页面、显示确认框或运行任务时暂停自动扫描；删除仍需明确确认，具体范围见[镜像管理与清理](../models/images.md#镜像管理与清理)。
公共基础、运行依赖、模型文件等类型的名称、用途和复用关系，见[镜像分类与复用](../models/images.md#镜像分类与复用)。
