# TUI 配置与测量行为

[← 返回专题目录](tui.md)

## 自动发现与选择任务

输入模型 ID 并启动后，准备流程先读取轻量元数据。翻译语言、摘要、问答等语义用途
保留为输入证据，但同一推理接口及解码计算配置只对应**一个推理组**。
只有发现多个独立推理组（如 Greedy 与 Beam、文本编码与生成）才显示
“选择采集任务”，可多选或全选；确认前不下载权重。组名称显示推理方式和其覆盖的用途数量，
而不把每种语言方向误显示为需要独立采集的对象。“返回配置”取消本次启动。
没有明确声明时仍可通过高级参数添加接口／workload，参见[任务发现与选择](../models/routing.md#任务发现与选择)。

已选推理组保存到实验集合；每组独立 Smoke、结果目录、矩阵与测量窗口。
同组仅保存一个代表输入模板，并在元数据中保留全部应用任务及原始声明。
某组失败后继续其他组，恢复时校验组指纹并保留已完成结果。
最近 CSV 只更新为本次实际新生成且审计通过的组结果。

## 实验配置与自动记忆

采集参数留在实验页。点击“高级参数”，切换到 batch size、Warmup、Repeat、请求窗口、采样
频率、连接/读取超时、可选固定 CPU 集合、分析器和任务覆盖参数等选项；点击“返回基本配置”回到模型和资源矩阵。
Warmup 和 Repeat 分别输入，次数、Hz 和 s 放在输入框右侧。采样频率、Idle 基线、冷却时间和请求超时
以两列排列，窄终端自动变为单列；整数不显示多余的 `.0`，已有小数精度保持不变。
拆分显示不改变命令参数或配置文件中的 `warmup`、`repeat` 等字段。
高级参数内的“记住实验配置”会保存当前实验表单，下次打开此项目时自动填入。
镜像默认校验后自动复用，缺失时自动构建。“镜像高级操作”默认折叠，其中“重新构建镜像（仅本次）”
只影响下一次采集或探测，启动后自动清除，也不会被“记住实验配置”保存；Docker 缓存仍可使用。
校验失败会明确停止，可在失败详情中选择“重新准备环境”。恢复实验必须使用原镜像，不能选择重建。
“识别覆盖 → 模型接口声明”接收本地 JSON 路径，运行采集和最大输入探测均传入 `--model-spec`。
例如 Ultravox 可填 `examples/multimodal/ultravox.model.json`；文件缺失或声明不合法时在启动前报错。
字段随实验配置保存，切换界面语言保留路径；协议与离线依赖见[模型声明](../models/pipelines.md#本地模型声明与自定义-pipeline)。
模型 ID 会在确认启动采集或最大输入探测时自动记住，无需点击保存；即使任务失败或被终止，
下次打开仍会填入该模型。仅修改输入、预览命令或取消确认不会更新记录。
模型的填入顺序为：命令行 `--model` → 最近启动的模型 → 手动保存的实验配置。
`--preset` 优先于保存的其他实验参数，并保留按上述顺序选出的模型。运行任务期间，配置控件暂时锁定。

### 结果路径

“绘图工具”的“结果 CSV”和“补采工具”的“结果目录”分别自动记忆，下次启动直接恢复。
确认采集时仅记住模型；本次输出目标保留在运行配置中。结束后只有确认属于本次 attempt 的新 CSV 才更新结果路径；
预检失败不会用目标目录中的旧 CSV 覆盖历史选择。仅有已完成 case 时，保留目录显示在监控详情中，便于续跑。
成功读取摘要或启动绘图时记住使用的 CSV，确认启动补采或补采计划时记住使用的目录，
按钮和快捷命令都适用。仅编辑输入框、无效路径或取消确认不会覆盖记录；最大输入探测不改动这两个结果路径。
路径保存只发生在子进程启动前或结束后、手动读取摘要后；测量期间禁用摘要读取。
统计页初始带入最近的结果 CSV；完成采集或更换已确认的 CSV 时，未另行编辑的统计路径会随之更新。
可直接编辑统计路径；手动输入的报告路径在切页和语言切换时保留，不另存为实验配置。
启动窗口统计会记住使用的 CSV，打开 JSON 报告不会改变采集、绘图或补采路径。

### 设置文件

设置文件按项目目录隔离，保存在 `$XDG_CONFIG_HOME/acprof/<项目路径哈希>/tui.json`；
未设置有效的 `XDG_CONFIG_HOME` 时使用 `~/.config/acprof/<项目路径哈希>/tui.json`。
设置页会显示完整保存位置。文件仅包含界面偏好、显式记住的实验默认参数、最近启动的模型 ID 和结果路径；
凭据由“连接与权限”写入独立的 `.env.local`。设置文件损坏时，界面提示并使用默认值，自动记忆不会覆盖原文件；
下一次主动保存设置后恢复自动记忆。自动记忆保存失败会提示，但不阻止任务启动或结果读取。

## 日志查看与复制

监控页显示状态摘要和日志；阶段、当前 case、已完成数量和资源配置集中在顶部，剩余空间用于日志。
“警告 / 错误”标签在窄窗口中保持单行，计数显示在右侧。
日志区域紧接状态摘要，复制、回到底部、放大和清空操作集中在底部工具栏。
状态摘要、日志区域及其工具栏统一融入页面背景，日志保留焦点边框、文本选区高亮和可辨认的滚动滑块。
日志是只读文本：鼠标拖动选择，双击选词，`Ctrl+A` 全选，`Ctrl+C` 或“复制选区”复制当前视图文字。
屏幕上的自动换行不会变成额外换行；系统剪贴板通过终端的 OSC 52 通道写入，
需要终端允许该功能。点击“放大日志”、按 `F8` 或输入 `/log` 可铺满终端，`Esc` 或“返回监控”恢复。
放大时仍可复制、清空和终止任务。滚动查看历史或选择文字后暂停跟随，新增日志继续保留，
点击“回到底部”恢复自动跟随。滚动条使用与主题一致的整格滑块，避免半格字形形成黑色断带。

点击“工具”（悬停提示“筛选 / 搜索”）展开筛选和搜索；级别下拉框提供全部、INFO、WARN、ERROR、DEBUG；SUCCESS 是 INFO 中的成功展示状态。
级别标签随主题配色，警告、错误和成功结果突出显示；路径和哈希降低视觉权重，错误上下文不弱化。
`NO_COLOR` 使用 Textual 的无颜色渲染，原有文字标签仍可阅读。外部日志不解释为 Rich markup。

默认摘要视图折叠已识别的 Docker 构建细节和 JSON，并合并同一上下文中连续相同的警告、显示次数。
发现 Docker 构建错误后恢复该上下文的构建输出。未知输出仍可见；勾选“详情”恢复完整保留内容。
搜索框按普通文字、不区分大小写匹配当前级别的保留原文，也会查找折叠内容；输入后显示匹配行，
Enter 或向下按钮转到下一个匹配，向上按钮转到上一个。清空搜索后恢复原视图，浏览与选择保持暂停跟随。

“复制原文”复制所有保留记录，不受搜索、级别或折叠影响；“导出”在任务空闲时将同一份文本保存到
TUI 设置文件旁的 `logs/retained-<唯一编号>.log`，完成通知给出路径。导出期间阻止启动新任务。
保留上限同时受设置中的原始行数（默认 5000）及 8 MiB UTF-8 字节数限制；超大单行被丢弃并计入
状态栏的超限计数，不静默截断。清空会清除保留内容和计数，不删除已经导出的文件。
这里的原文是 TUI 接收并保留的子进程文字，换行经过进程文本流规范化；它不是整个任务的无损字节归档。
正式测量期间被抑制的普通输出只有数量记录，不包含在复制或导出内容中；实验日志与结果产物仍使用既有路径。


界面显示前的两个队列也有独立上限，保留最早的少量上下文和最新的尾部：

| 队列 | 最多记录数 | UTF-8 文本总量 | 单条记录 |
| --- | --- | --- | --- |
| 待显示批次 | 5000 | 8 MiB | 1 MiB |
| 测量期延迟回放的诊断 | 512 | 1 MiB | 64 KiB |

超过单条上限的记录整条省略；超过总量时淘汰较早的尾部记录。回放时显示省略总数及其中超长记录数，
这些计数不重复相加。这里限制的是保留文本，不是 Python 进程总内存。
测量期间只更新有界队列和计数，不新增刷新计时器或日志落盘；进程清理未完成时仍保持静默，
已缓冲的诊断交给清理任务，确认退出后再回放。

RunState 建立后的准备失败与取消另有持久摘要和主进程日志：
见[准备阶段诊断](../profiling/artifacts.md#准备阶段诊断)。关闭 TUI 后仍可检查对应 attempt；
这些文件与手动导出的界面保留文字分别记录各自范围。

## 测量期间的界面行为

正式采集通过版本化边界事件控制静默状态，普通日志文字不再决定窗口开关。
停止、回调异常和卸载共用 SIGINT（30 秒）→ SIGTERM（5 秒）的清理策略；未确认退出时
显示“清理未完成”与 PID，保持忙碌，可以再次停止，不会提前显示完成或启动第二个任务。
默认不自动 SIGKILL；协议和退出限制见[进程与界面边界](../profiling/lifecycle.md#进程与界面边界)。


界面不会重写采集逻辑，而是启动现有 `acprof run`、`acprof probe`、`acprof plot`、`acprof stats` 和 `acprof profile`。为了降低
对能耗与延迟实验的影响，正式 workload 窗口内停止常规日志重绘，不运行实时绘图，
也不轮询正在写入的 CSV；状态仅从已有进程输出中事件驱动更新。TUI 内运行时还会
禁用子进程的 tmux pane 捕获，避免把全屏 ANSI 重绘写进 `logs/terminal.log`（旧目录为 `tmux_all.log`）。论文复现仍可
直接复制界面显示的完整命令，在普通 CLI 或自动化脚本中执行。

准备阶段的日志批量追加，通常最多每 250 ms 刷新一批；达到 128 行或 64 KiB 待显示文字时提前提交，
防止积压。进入正式测量时停止待执行的刷新，禁用搜索、筛选、详情、原文复制和导出；退出或失败后恢复。
普通追加只投影新增记录，跨批次重复警告继续累计折叠次数。后到的 Docker 错误会重新投影
对应 scope，恢复之前隐藏的失败上下文；过滤条件改变或历史淘汰时重建视图。
选择、搜索、滚动锚点及原始日志导出语义保持一致，正式测量期间仍暂停刷新。
增量更新设计参考 [Textual Log.write_lines](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/widgets/_log.py)
（MIT），复用现有 TextArea API，不增加依赖。

日志中的阶段耗时仅是界面观察的墙钟时间，不是实验 latency 指标。下载事件不得进入正式测量窗口。


## 下载与磁盘预检

模型 ID 旁选择“模型来源”（Hugging Face／ModelScope）。切换模型 ID 或来源时，清除旧候选自动填入的 revision，保留用户手动改写的 revision。下载策略固定显示“自动”，网络显示“使用系统网络环境”。旧设置中的下载模式迁移为 `auto`，旧代理字段忽略，不修改进程已有代理环境。

准备先检查本地模型，再自动处理入口和可信存储重定向。无完整缓存时查询大小、磁盘和预算，然后执行 HEAD 与限量 Range GET：所有模型探测共享至多 256 KiB 正文读取，包含少量真实模型数据，计入预算且不写入缓存。零预算或预留完整下载后余量不足时跳过 GET。完整缓存跳过网络。存在待下载量或未知量时弹出计划确认；设置了预算且大小未知或超限时先报错，不能通过确认绕过预算。所有预检在正式测量前，测量窗口不扫描磁盘或查询下载源。

HF 下载路径耗尽时，默认正文显示“无法获取 Hugging Face 模型”、失败阶段与最终 host，底部提供“返回配置”“重试”“改用 ModelScope”，悬停可查看各操作的实际行为。下载失败记录与 traceback 位于默认展开的详细信息，可像日志一样滚动、选择和复制。切换 ModelScope 时需明确填写目标 ID／revision 并确认，取消则保留 HF；确认后终止旧准备流程、建立独立输出目录并返回配置，不自动开始新实验。不同 source 的同名模型保持独立缓存和实验身份。

“下载确认”按“下载概览”“运行环境与来源”“存储空间”“网络预检”分区，用标题和分隔线区分内容，所有信息直接展开。
预计下载、预算、模型缓存和入口放在概览；Runtime 与依赖来源放在运行环境区；可用与下载后剩余空间、Docker 存储和 Model Store 路径放在存储区。
网络区保留模型来源、探测目标 host、HTTP 状态、接收量、耗时与探测边界。页面没有“高级详情”折叠项或原始 JSON。
网络状态为“通过”“失败”“未验证”，失败原因直接可见；
HEAD/manifest 只验证元数据，限量 GET 通过也不保证完整模型必然下载成功。详细边界见 [Model Store](../models/model-store.md)。
内容可滚动，底部“终止任务”“确认下载”固定可达；确认后才开始完整模型下载与 Runtime 安装。Esc 进入终止确认。
模型信息尚有未决字段时，仍使用“应用字段”提交选择，解析完成后再点击“确定”。

下载摘要、Model Store、镜像大小与存储空间统一按原始 bytes 的数量级显示十进制单位：
小于 1,000 显示 B，小于 1,000,000 显示 KB，小于 1,000,000,000 显示 MB，其余显示 GB。
B 保留整数，较大单位显示约三位有效数字，例如 `708 MB`、`794 B`、`33.0 GB`。
格式化仅发生在 TUI 展示层；内部数据、JSON、预算判断和后续计算仍使用原始 bytes，未知值不会转成零。

下载完成后同一区域显示已校验的新增模型 payload、cache savings；未知 wire bytes 不显示成零。

监控页将接口解析、运行验证和测量状态并列显示；下载区独立展示模型与状态、文件数据进度条，以及对齐的文件数、缓存、网络 payload、速度和剩余时间。
进行中使用主题强调色，完成为绿色，校验／待确认／取消为黄色，失败为红色，未开始和未知值弱化；状态文字始终保留，`NO_COLOR` 下也能区分。
长模型名和重试说明在下载区内换行；小窗口中超出高度时可滚动，聚焦后用方向键或 Home / End 浏览，底部操作栏保持可达。
文件数据量包含缓存及续传内容；只有校验通过后显示“模型文件已校验”，随后仍可能有运行验证等准备阶段。
Hugging Face 使用 SDK 的聚合字节回调，网络 payload 与文件重建量分别计数；续传已有内容不计入网络速度，
重试已接收的数据可以再次计入传输累计。该量不含 HTTP/TLS 等开销，不写入原有 `wire_bytes` 字段。
Xet 压缩和去重意味着网络字节总量不可由文件大小推导，因此剩余时间显示未知；速度没有有效时间样本时也显示未知。
ModelScope 目前只有准备、校验和结果状态，无法取得的实时字节数或速度明确显示未知。
全部命中本地缓存时不会为了进度请求网络；失败、取消和 endpoint 重试分别保留状态或尝试编号。
缓存量记录本轮准备开始时的完整缓存。切换 endpoint 重试后，已完成文件可能成为新缓存，
聚合回调无法重建完整基线，因此字节百分比暂时显示未知，校验阶段恢复；网络传输累计继续保留。

准备期进度使用独立、版本化的 `ACPROF_DOWNLOAD` 消息，只在 TUI 子进程中启用，节流到每 250 ms
一次，状态变化立即发送。普通 CLI、CI 和重定向保留 SDK 自身的输出策略。已有 `ACPROF_EVENT`、
`ACPROF_PREPARATION`、下载 provenance 和实验结果协议不变。
进度条只随现有事件更新；未知百分比保留“未知”，不播放不确定进度动画，也不新增刷新计时器。
“Model Store 占用与清理”先显示总量、各模型和 free space，再加载 LRU 删除预览。
若缓存锁由另一任务持有，面板显示等待原因；关闭按钮或 Esc 可以取消等待与扫描，无需等下载任务结束。
后台读取释放资源后关闭面板并恢复实验操作，避免残留扫描与随后启动的测量重叠。

清理仍需确认，删除前在锁内复检活动 lease、共享权重和批准范围，预览后新增的模型会保留。
实际删除已经开始时先完成锁内收尾，再处理关闭请求；运行和测量期间不能打开清理面板。

Model Store 清理命令和 lease/LRU 语义见[下载网络与 Model Store](../models/model-store.md#下载网络与-model-store)。真实终端效果需另验，headless 交互不代替 SSH/VS Code 客户端验证。

### 结果质量证据

读取结果摘要或窗口统计报告时，界面分别显示运行状态、正式窗口完整性和质量状态。
`weights_reinitialized` 等影响输出且未确认合理的证据会显示 `blocked` 并暂停默认自动优选；
缺少历史证据或无法解释的告警显示 `unknown`。原数值、质量原因和来源继续可查，运行成功不掩盖质量问题。
质量字段与独立比较定义见[指标与结果分析](../results/comparisons.md#跨独立实验比较)。
