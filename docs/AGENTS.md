# 文档维护约束

- 用[文档导航](README.md)确定每个主题的唯一维护位置。文档解释原理与契约，执行步骤放入对应 Skill；用户命令示例可保留在根 README。
- 移动或删除文档后修复入站链接，使导航直接指向对应专题。字段或参数不在导航中另存副本。
- 按任务关联的主题分组，优先增加已有章节；新文档必须能从根 Agent 导航或本目录索引到达。
- 普通重构不自动创建按日期命名的 Markdown 实施报告。一次性计划、测试日志和验收快照放在被 Git 忽略的 `internal-testing/` 或关联任务记录中；必要的历史证据可由 Git 提交恢复。
- 归档报告前，将仍然有效的架构、测试方法和约束整理到对应权威专题；重要的长期技术决策再独立记录背景、取舍与影响，不在文档目录积累重复的阶段性报告。

链接、锚点和 Skill 的验证方式见[测试指南](development/documentation-checks.md#文档与-skill-检查)。
