# AC-Prof 长期 Roadmap（Alpha）

**目标：** 让 AC-Prof 成为真正可用、可扩展的模型推理画像工具，完成
**模型发现 → 配置 → 真实采集 → 结果分析** 的完整流程。

当前优先 **功能闭环、通用适配、TUI 体验和科研可信度**。
除严重安全问题、错误测量或数据损坏外，暂缓缺少实际收益的锁、缓存、哈希等微优化；
不为重构而重构。

## 里程碑

| 阶段 | 重点 | 怎样算完成 | 状态 |
| --- | --- | --- | --- |
| M0 · 能力盘点 | 找出真实可用与尚未验证的功能 | 形成有实际证据的模型、Runtime、采集能力清单 | **当前** |
| M1 · 采集闭环 | 从模型准备到结果分析全流程 | 真实模型在 Process CPU basic、具备条件时的 Native Docker full 跑通；指标有明确语义 | 待做 |
| M2 · 通用适配 | 模型与任务族扩展 | 多个代表性真实模型通过统一接口运行，新增适配尽量不依赖模型 ID 特判 | 待做 |
| M3 · Runtime / Profiler | 统一扩展能力和采集边界 | 不同环境、采集器有清晰的能力声明、生命周期和验证结果 | 待做 |
| M4 · TUI 体验 | 完整、简洁的操作流程 | 在真实终端中完成配置、运行、诊断、恢复与结果查看 | 待做，可并行 |
| M5 · 科研结果 | 可解释、可复现、可比较 | 输入与推理参数、指标、CSV、统计和报告一致，缺失能力不误报 | 待做 |
| M6 · 交付使用 | 安装、文档与发布 | 干净环境能安装、运行示例、导出结果和排查常见问题 | 待做 |

## 现在做什么

**先完成 M0，不急着再次重构。**

1. 盘点已有功能和测试证据，区分 **已真实验证 / 仅模拟或接口测试 / 未验证 / 受阻**。
2. 找到真正阻碍用户完成实验的缺口，优先选择轻量真实模型验证 Process CPU basic 闭环。
3. 根据实际发现更新里程碑顺序，再推进下一项最有长期价值的建设任务。

“代码已实现”“测试通过”不等于“真实模型采集成功”；完成状态必须附验证记录。
正式测量、大型下载或付费资源遵守已有授权与预算约束。

## 如何持续更新

- 每轮优先选择当前里程碑中**影响范围大、能实际解锁能力**的任务。
- 完成后更新状态、证据链接和**下一项任务**；详细日志留在测试记录，不堆到此页。
- 每个里程碑完成或每 2–4 周重新评估优先级，允许增删目标，长期持续演进。
- 不因发现局部优化点就偏离当前建设目标；安全、数据正确性和核心流程阻塞例外。
