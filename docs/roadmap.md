## **目标：** 持续推进 AC-Prof 的功能完善、通用架构、模型适配、采集能力、TUI 体验、科研数据质量与长期可维护性。



## 注意事项

* 暂缓缺少实际收益的锁、缓存、哈希等微优化；
* 不得通过制造不必要的技术债任务维持持续开发。



## 持续执行机制

1. 根据项目当前成熟度，识别长期发展方向。
2. 维护可动态调整的 Roadmap，区分已完成、已实现未验证、待建设和暂缓项目。
3. 优先选择能够提升系统整体能力、扩展性和真实可用性的任务。
4. 围绕当前里程碑持续开发，直到达到明确的验收标准。
5. 每完成一个里程碑，重新检查项目现状、技术生态和新的能力缺口。
6. 根据新的发现更新路线图，并继续下一个高价值建设目标。



## 里程碑

| 阶段                     | 重点                         | 怎样算完成                                                                         | 状态           |
| ------------------------ | ---------------------------- | ---------------------------------------------------------------------------------- | -------------- |
| M0 · 能力盘点           | 找出真实可用与尚未验证的功能 | 形成有实际证据的模型、Runtime、采集能力清单                                        | **当前** |
| M1 · 采集闭环           | 从模型准备到结果分析全流程   | 真实模型在 Process CPU basic、具备条件时的 Native Docker full 跑通；指标有明确语义 | 待做           |
| M2 · 通用适配           | 模型与任务族扩展             | 多个代表性真实模型通过统一接口运行，新增适配尽量不依赖模型 ID 特判                 | 待做           |
| M3 · Runtime / Profiler | 统一扩展能力和采集边界       | 不同环境、采集器有清晰的能力声明、生命周期和验证结果                               | 待做           |
| M4 · TUI 体验           | 完整、简洁的操作流程         | 在真实终端中完成配置、运行、诊断、恢复与结果查看                                   | 待做           |
| M5 · 科研结果           | 可解释、可复现、可比较       | 输入与推理参数、指标、CSV、统计和报告一致，缺失能力不误报                          | 待做           |
| M6 · 交付使用           | 安装、文档与发布             | 干净环境能安装、运行示例、导出结果和排查常见问题                                   | 待做           |
