# 终端界面使用指南

TUI 提供实验配置、运行监控、绘图、统计、补采、镜像管理和设置。
先完成[安装与主机准备](Getting_Started.md#快速开始)，再启动界面。
设置文件格式与颜色参数见 [CLI 与设置](CLI_Reference.md#tui-本地设置)。

顶栏始终显示 `Native Linux / FULL` 或 `WSL2 / PARTIAL`（未支持环境显示 unknown）。
采集确认页列出会采、语义降级与缺失指标；WSL2 的 full 或未开放 profiler 请求会在启动前拒绝。
平台策略见 [WSL2](platforms/wsl2.md)，这些界面显示不进入正式测量窗口。

## 启动和页面

首次 clone 可以运行 `./setup.sh`，完成安装和 basic 环境检查后自动进入入门配置。
通过此脚本或其他[发行包方式](Distribution.md)安装后，统一使用 `acprof tui` 启动全屏 TUI：

```bash
acprof tui
```

也可以预填模型并直接加载最小 smoke 配置：

```bash
acprof tui --model google-bert/bert-base-uncased --preset smoke
```

smoke 预设使用 `basic`、CPU、1 核、4 GB、输入规模 64、无 warmup 和单次请求，关闭独立 profiler 与通知。
需要完整采集时在“高级参数”中改为 `full`；主矩阵和完整默认预设仍为 `full`。
两种模式的主机条件和指标范围见[采集协议](Profiling_Protocol.md#profiling-mode-与能力证据)。

预设匹配只比较实验参数。输出目录、下载策略、缓存、通知、恢复和镜像复用设置不会改变预设身份；
修改 CPU、输入规模、重复次数等参数后显示“预设名 · 已调整”，恢复原参数后恢复原标签。

`--output-dir` 覆盖预设或已保存配置中的输出目录，例如
`acprof tui --model google-bert/bert-base-uncased --preset smoke --output-dir results/my-first-run`。
启动参数只预填本次界面，打开或退出界面不会覆盖已保存的实验默认值；不传参数时继续恢复原来的设置。
`setup.sh` 每次使用新的结果目录，直接运行 smoke 时默认仍为 `results/smoke`，重做实验需更换目录。

默认以 RGB 真彩色显示，默认主题为“石墨灰 · 深色”，普通终端和 VS Code 使用相同配色；SSH 未传递 `COLORTERM`
也不会自动降级。仅支持 256 色的终端可加 `--color-system 256`，需要环境自动检测时使用
`--color-system auto`；具体行为见[终端颜色说明](CLI_Reference.md#tui-终端颜色)。

TUI 分为“实验配置”“运行监控”“绘图工具”“统计报告”“补采工具”“镜像管理”和“应用设置”七页。
“应用设置”固定在顶部导航栏最右侧，其余页面靠左排列；中英文切换和终端缩放后保持这一布局。
页面统一为顶部导航、页面标题或状态摘要、主内容、底部操作栏；主内容滚动时，摘要和操作栏保持可见。
底栏左侧集中放置导航和次要动作（如高级参数、读取摘要、查看补采计划、日志工具），
右侧放置本页主操作。按钮随中英文标签调整宽度，缩窄终端后仍按左右分组排列。
绘图摘要和统计表格采用无外框内容区，仅保留一条分隔线；输入框和操作按钮仍保留焦点边框。
“开始采集”“生成图表”“计算统计”“执行补采”“删除所选”“保存设置”固定在各页右下角，
监控页的日志工具和“终止任务”位于底栏，放大日志后仍可操作。可选的快捷命令框位于页面操作栏下方。
实验页集中填写模型、资源矩阵和输入规模，提供三种预设及自动命令预览；底栏提供最大输入探测。
每次启动自动在后台检查环境；仅有警告或错误时，页头才出现环境状态入口。
表单会随终端宽度切换排列。监控页显示 case 级进度和日志；绘图页通过结果 CSV 读取摘要、生成图表，
补采页通过结果目录选择 profiler、查看补采计划或执行补采。绘图和补采任务启动后切换到监控页查看日志。
`/results`、`/summary` 读取摘要后打开绘图页。开始探测、采集和执行补采前都会显示确认页。

按钮、快捷键和快捷命令使用同一套任务状态。环境检查、统计、补采、资源清理期间不能再启动采集；
“终止任务”只在存在仍在运行的受控子进程时可用；退出后的产物核验继续锁定采集入口，但不再提供终止操作。
摘要、报告读取期间可以切换路径、重新读取或退出，
迟到结果不会覆盖新选择。`/cancel` 可取消当前结果读取；后台读取实际结束前仍禁止启动采集。

### 实验结束与结果摘要

最终状态分为“已完成”“部分完成”“已停止”“失败”和“清理未完成”。日志报告完成后先显示“核验产物”；退出码 0 本身不能证明实验完成。
采集或探测在预检时发现不支持的任务，会保留“任务不支持”状态、具体原因和处理办法。
TUI 关联当前子进程与 `run_state` 中新增的 attempt，再通过既有产物布局、计划覆盖审计及能力报告核对完成范围。
停止后保留已写入的 case，监控详情显示保留目录及续跑提示。进程未确认退出时继续保留所有权、禁用新的采集，
可再次请求停止。

目标目录中已有 CSV 不代表本次生成结果。预检失败或没有本次产物时显示“本次未产生结果”，
历史结果仍可通过原路径读取；恢复一个已完成实验会说明本次未重新采集。

摘要在后台读取，按现有窗口统计的 CPU、内存上限、GPU、输入规模和环境分组，展示可用的延迟、吞吐量、
内存及能耗窗口均值。只统计 `status=ok`、`warmup=0`，不计算跨配置的总体平均或“最快配置”。
窗口不足时明确标记；摘要不执行 bootstrap，置信区间需主动计算统计报告。
摘要最多展示前 30 个配置，更多配置请用统计报告；缺少配置身份字段的历史 CSV 只显示行数及缺失原因。
读取失败保留可操作界面。所有读取和统计都位于正式测量窗口之外。

### 数值状态

| 显示 | 含义 |
| --- | --- |
| `—` | 不适用，例如尚未开始任务的运行时间、CPU 实验中的 GPU 能耗 |
| `…` | 正在计算或读取，完成或失败后更新为结果或错误说明 |
| `未知` | 无法确定，例如无法核验的镜像大小、缺失的数据或样本不足的统计区间 |

真实的零仍显示为 `0` 或带单位的零。未知数值不附加单位；英文界面将 `未知` 显示为 `Unknown`。
统计表的说明和镜像诊断保留缺失原因；进度日志、CSV 和报告 JSON 的原始值不受显示规则影响。

## 统计报告

“统计报告”页可查看窗口置信区间、CPU/GPU 监测开销和 CLI/TUI 对照：

- 采集结束后，统计路径会自动带入结果 CSV（保留已手动编辑的路径）；确认路径后点击“计算统计”，也可输入其他实验目录或 CSV。
  计算调用 `stats.py`，新报告保存到 v2 结果目录的 `plots/analysis/window-statistics-YYYYMMDD-HHMMSS-ffffff.json`（旧目录继续使用 `analysis/`），使用本地日期、时间和六位微秒。
  保存前比较该目录已有 JSON 的完整内容；相同则提示“已有相同报告”及路径，并直接显示已有报告，不新增文件。旧 UUID 文件名也参与比较，JSON 缩进或字段顺序不影响判断。
  源 CSV、统计参数或统计结果不同会保存新报告；旧报告保留，时间戳重名时递增微秒避免覆盖。
- 查看已生成的报告时，输入 JSON 路径后点击“查看报告”。表格支持方向键、滚动和选行查看口径；延迟以 ms 显示。
- `/stats [csv/dir]` 计算统计，`/report [json]` 打开报告。计算需要空闲；读取期间可以选择另一份报告，原始 CSV 与旧报告保留。

窗口统计需要主动点击，不会在每次采集后自动计算；监测开销及 CLI/TUI 对照仍由独立工具运行，
本页读取它们已经生成的报告。统计口径、默认指标与样本不足的说明见[指标分析](Metrics.md#窗口置信区间与开销对照)。

## 表格列宽

所有 TUI 表格（统计报告、镜像树、镜像列表、层共享）均支持按住表头相邻列之间的 `│` 左右拖动，手动调整左侧列宽；最后一列右侧不显示拖动手柄。
表头与单元格内容统一左对齐，镜像树名称保留层级缩进；拖动改宽后保持对齐。
空表格的表头横条和已有表头右侧的留白不触发选择或排序；行尾留白仍可定位到对应行。
松开鼠标结束；拖动不触发排序、勾选或折叠。一般列最窄保留一个字符格，镜像树名称列另保留层级箭头与勾选空间。
手动列宽在本次会话的排序、筛选、刷新、视图与语言切换、终端缩放后保留，重启 TUI 后恢复默认；任务运行期间暂停拖动。

## 镜像管理

“镜像管理”页（`/images`）默认打开可折叠的**镜像树**，可切换到**镜像列表**或**层共享**。
右上角“存储空间”打开独立弹窗，显示 Docker 数据目录、所在磁盘的容量与使用率、镜像／容器／Volume／Build Cache 的占用与可回收量，以及当前勾选镜像的释放估算和删除后可用空间。
打开弹窗时读取一次，点击“刷新”重新查询；“关闭 (Esc)”或 `Esc` 返回镜像页并保留勾选。小窗口中内容可滚动，底部按钮固定可见。
数值使用 GiB，较小数据用 MiB、KiB 或 B；无法核验的值显示“未知”。释放量仅是按共享层去重后的估算上限，缓存可能继续占用数据；弹窗不执行删除或清理。
磁盘“可用”不含文件系统预留块，远程或虚拟机 Docker 无法核验本机磁盘时显示未知。查询期间禁止启动采集；即使关闭弹窗，仍等后台查询结束后恢复启动入口。
打开页面自动读取清单，空闲时每轮读取完成后 5 秒更新；刷新保留有效勾选、筛选、折叠和浏览位置。
树中显示逻辑名称、完整大小与相对父镜像的新增大小；搜索支持包名和版本，并保留祖先路径。
平台节点统一显示 `Python CPU`、`PyTorch CPU`、`PyTorch CUDA 12.4`、`PyTorch CUDA 12.8`，同平台子节点省略重复后缀；依赖版本号保留小数点。
`←/→` 或树的箭头折叠/展开；树和列表中，点击 `□ / ☑` 及左右各一格留白勾选/取消，点击行内其他位置只查看详情。
镜像树左侧会高亮通往当前行的祖先连接线，随鼠标点击或方向键移动更新。
空格可切换当前镜像的勾选状态；列表表头可排序。镜像列表只固定最左侧勾选列，“环境 / 模型”与大小、`Repository`、`Tag` 等数据列一起横向滚动。
详情先显示镜像摘要（名称、类型、大小、容器引用数与删除释放估算），下方“依赖清单”“镜像信息”“诊断信息”默认折叠。
按住列表与详情之间的“↕ 拖动调整详情高度”分隔条上下拖动：向上扩大详情，向下扩大列表。
分隔条可用 `Tab` 聚焦，`↑/↓` 微调、`Home` 恢复默认高度；高度在本次会话保留，缩小终端时自动限制，放大后恢复。两侧内容仍可独立滚动。
点击分组标题，或用 `Tab` 聚焦后按 `Enter` 展开；依赖标题显示包数量、“无新增包”或“未知”，展开后逐行查看完整包版本。
“镜像信息”显示继承路径、共享/独有空间、模型、标签与容器；完整 SHA、依赖来源、history 核验和空间计算说明放在“诊断信息”。
切换语言、缩放窗口或勾选同一镜像时保留展开状态；换一个镜像时回到折叠摘要。依赖按镜像身份匹配锁，运行依赖层扣除平台已有包；层共享视图也将引用镜像与诊断标识分组。
“选择同模型”会选中该模型的服务、权重和调试镜像，保留公共依赖。点击“删除所选”后，核对全部标签并确认。
已有容器引用的镜像不能删除；仍需续采或补采时应保留原实验镜像。页面按 image ID 合并别名，大小包含共享层，
释放估算按所选集合去重，构建缓存仍可能保留数据；`?` 表示未知。
离开页面、显示确认框或运行任务时暂停自动扫描；删除仍需明确确认，具体范围见[镜像管理与清理](Runtime_Compatibility.md#镜像管理与清理)。
公共基础、运行依赖、模型文件等类型的名称、用途和复用关系，见[镜像分类与复用](Runtime_Compatibility.md#镜像分类与复用)。

## 快捷键与退出

`F2` 或 `/settings` 打开应用设置，`F5` 开始采集，`F6` 执行环境检查，`Ctrl+X` 安全终止当前任务。
点击界面右上角的“×”或按 `Ctrl+Q` 退出；任务运行中会提示先安全终止任务。
底部输入框还支持 `/run`、`/probe`、`/check`、`/status`、`/stop`、`/plot`、`/stats`、`/report`、`/images`、`/profile` 和 `/help`
等快捷命令。

### VS Code 中的 Ctrl+Q

如果 `Ctrl+Q` 在普通终端有效、在 VS Code 集成终端无效，可能是按键被 VS Code 拦截。
Windows 客户端默认将它绑定到“快速打开视图”（`workbench.action.quickOpenView`）；
Remote-SSH 也由发起连接的客户端处理快捷键。在 VS Code 工作区设置 JSON 中加入
以下配置；已有 `terminal.integrated.commandsToSkipShell` 数组时，将该条目追加进去：

```json
{
  "terminal.integrated.commandsToSkipShell": [
    "-workbench.action.quickOpenView"
  ]
}
```

前缀 `-` 表示将该命令移出终端按键拦截名单，让终端应用接收按键。
参见 [VS Code 官方终端快捷键说明](https://code.visualstudio.com/docs/terminal/advanced#_keyboard-shortcuts-and-the-shell)。
保存后点击终端让其获得焦点，再按 `Ctrl+Q`。若仍无效，运行命令面板中的
`Developer: Toggle Keyboard Shortcuts Troubleshooting`，再按一次 `Ctrl+Q`，查看
快捷键日志中实际匹配的命令，以排查扩展或自定义绑定；排查后再次运行该命令关闭日志。
也可以点击右上角“×”，或在底部快捷命令框输入 `/quit` 退出。

## 环境检查

TUI 每次启动在首屏刷新后自动执行一次环境 preflight，不需要填写模型 ID。
检查异步进行，保留当前页面、焦点和表单编辑；完成前“开始采集”暂不可用，并显示等待原因。
正常结果静默处理，不弹成功通知、不追加运行日志、不切换页面。

警告或错误通过页头的“环境警告”或“环境异常”入口查看详细原因，详情中提供“重新检查”。
阻断性错误会禁用“开始采集”，在实验页和按钮提示中解释原因；`F5`、`/run` 以及确认后的启动
使用同一阻断结果。非阻断警告只说明对应能力的限制，不禁用其他采集。
检查异常或未能取得测量锁时保留错误状态，修复后重新检查，成功后自动移除异常入口。
`F6` 和 `/check` 也可主动重新检查；检查期间重复请求不会产生并行探测。

GPU、采集模式、抓包网卡或 profiler 选择变化后，已有检查失效，需重新检查；修改模型 ID 或资源
矩阵不触发重复探测。检查期间修改相关配置也不会让旧结果解锁新配置。
检查与本进程的采集、补采、清理等任务互斥，并持有同用户的测量锁，避免干扰另一进程的正式窗口。

环境检查不会启动模型或正式采集。`perf instructions` 与正式启动共用权限探测，以当前用户
直接运行 perf；同时读到有效指令计数、通过主机 PID 1 的跨用户附加检查才显示通过。
这会提前发现 `perf_event_paranoid=-1` 但缺少容器进程访问权限的问题。
权限不足时可在 `F2` → “连接与权限 → 采集权限”处理，或参照
[最小权限安装](Getting_Started.md#最小权限安装)。旧的 sudo 密码配置会明确报错；检查不会修改系统权限，
正式启动时仍会执行完整预检。

检查只突出本次请求的能力。`basic` 未选择的 RAPL、perf 和抓包指标保持 `not_requested`，不探测、
不计入“通过”，也不产生异常入口；这不证明该能力可用。`full` 仍要求 RAPL、perf 和抓包能力，
缺失时阻止该次 FULL 采集，不会自动改为 `basic`。未选择的 GPU 能力不会阻止 CPU 采集。

## 输入与确认

表单输入框、选择框及其展开菜单默认使用 `solid` 细线边框，普通、聚焦和禁用状态保持同一种线框。
这减少了对终端拼接 `tall` 块状字符的依赖，无需额外设置。终端仍需支持 UTF-8、中文字体和
基础 Unicode 线框；`--color-system` 只调整颜色深度，不改变字体或边框字符，也不提供纯 ASCII 界面。
底色统一透明，随所在页面的背景变化；悬停、聚焦时也不叠加底色，聚焦通过青色边框提示。
输入文字的选区和展开菜单的当前选项仍保留高亮，便于编辑和选择。

所有输入框均支持 `Ctrl+A` 全选当前框内的文本；全选后键入或粘贴会替换全文，
按 `Backspace` 或 `Delete` 清空。`Home` 仍移到行首，`Ctrl+Shift+A` 也可全选。
输入框使用细竖线插入光标，停下输入后亮 0.5 秒、灭 0.5 秒；键入、移动或点击后立即显示。
TUI 直接控制光标亮灭，不依赖终端的闪烁设置，也不为闪烁重绘界面。离开输入框后隐藏并停止
计时，正式测量窗口内暂停闪烁。光标形状需要终端支持 DECSCUSR；退出或挂起 TUI 时重置样式。

操作按钮统一使用透明底色和细线圆角边框，颜色含义不随主题变化：青色表示当前选择或主要操作，
普通白色表示一般操作，黄色表示补采等有风险但可恢复的操作，红色表示删除或终止，灰色表示禁用，
绿色表示成功或服务就绪。浅色主题用深色普通文字及较深的同色系操作颜色保持可读性。
悬停或键盘聚焦时加粗并加下划线，保留操作本身的颜色；禁用时统一变灰。
日志工具栏和确认弹窗也使用相同语义，删除、终止的确认按钮保持红色，补采确认保持黄色。
确认弹窗打开时不预选按钮；使用鼠标时，移入按钮才高亮，移出后恢复。
键盘操作使用 `Tab` / `Shift+Tab` 选择按钮，`Enter` 执行所选操作，`Esc` 取消；未选择时直接按 `Enter` 不执行操作。

操作通知显示在右下角，可点击关闭。通知覆盖按钮、切换窗口尺寸或隐藏快捷命令栏时，
中文提示应保持完整；这项显示修复同时适用于 VS Code、Antigravity 和其他终端。

### 模型契约解析与验证

“开始采集”是正常入口。采集进程自动解析模型，选择唯一可确定的 task、family、backend、adapter
和 runtime profile，再执行主机预检、镜像及输入准备、目标 CPU／GPU 环境的完整运行验证。
验证通过后继续正式测量，不需要先手动运行 basic／full Probe。

只有存在可由用户裁决的任务、Pipeline、输入映射或依赖选择时，才弹出“需要你确认”。
弹窗只显示未决字段，提供候选选项或必要的 JSON 输入；“确认并继续”将答案交回原采集进程，
无需重新点击开始。网络、权限、文件缺失和 runtime exception 显示具体错误，不作为适配选择。
已知依赖访问失败不能通过取消该依赖绕过。

选择优先级为：用户显式配置 → 当前证据对应的已确认选择 → 自动推断 → 询问用户。
显式配置与接口声明不兼容时明确报错，不偷偷改写用户配置或模型声明。确认选择保存在输出根目录的
`.model-contracts/decisions/`，以模型 SHA、静态证据／resolver 身份和显式配置隔离；证据或配置变化
后重新裁决。缓存不保存可复用的运行验证结论。

运行监控分开展示“接口解析／运行验证／测量”。例如“通过／失败／未开始”表示接口已经确定，
实际环境验证失败，尚未测量。修复后“重新验证”仅重试当前运行验证，保留原模型、不可变镜像和输入
计划。若修复涉及镜像内代码或依赖，选择“重新准备环境”：保留解析结果，重新准备镜像、输入和验证。
失败验证的报告、相关日志和输入／解析证据保存在日志目录的 `runtime-attempts/`，重试不会抹掉失败原因。
重试不自动修改 CPU／GPU、内存、采样或模型 revision。等待期间可终止任务；退出 TUI 后不会保留
等待中的子进程。跨进程恢复仍遵循原有实验续跑校验，不等同于这里的阶段重试。
续跑可复用通过校验的原运行验证；旧实验若没有成功验证记录，交互采集会明确报错，需使用新实验目录验证，
以保留原实验冻结的证据。

“高级诊断 → 模型检查”保留为可选 Inspect 工具。它读取模型证据，摘要展示固定 revision、adapter、
runtime profile 以及分阶段状态；已解析字段及来源默认
折叠。只有缺失输入、依赖或 Pipeline 选择出现编辑框，输入该字段的 JSON 值即可应用。
嵌套对话可填写 `{"template":[{"role":"user","content":{"from":"text"}}]}`；依赖选择填写
`[{"repo_id":"org/model","role":"tokenizer"}]`，SHA 和文件选择自动解析。确认不使用的候选可设
`required:false`。不支持的动态源码／任务冲突会说明需要本地声明或 adapter，不能一键忽略。

“使用契约”写入输出根目录下独立的 `.model-contracts/<模型>/<id>/acprof_model.json` 与解释报告，将路径填入运行表单，
不覆盖作者文件。basic／full Probe 同样先保存，再交给任务监控页执行，可使用现有停止按钮取消。
默认 CPU 2 核、4 GiB；basic 不加载模型权重或推理，full 执行一次最小输入推理，镜像准备可能下载模型。
再次打开解析窗口可查看这次 Probe 的报告。主模型 revision 在审阅后变化时需重新解析；保存的 v1
本地声明是执行接口，不将以后运行的主模型 revision 永久固定。需要重新读取 Hub 时清除模型接口
声明框中的生成路径后再解析；仍可手动选择原声明。测量期间禁用解析入口，不启动额外 Probe。

## 界面偏好

“应用设置”页按功能分成三个带标题的区块：

- **界面与交互**：界面语言、界面主题、底部快捷命令框。
- **日志**：保留日志行数、日志自动换行。
- **连接与权限**：说明连接与采集权限的用途，提供“管理连接与权限”入口。

区块按上述顺序纵向排列；窗口较小时可滚动，底部“恢复界面默认”和“保存设置”始终可见。
“管理连接与权限”入口可填写 Hugging Face Token、镜像源、备用地址、代理和企业微信 Webhook。
敏感字段默认遮蔽；底部操作栏中“关闭”右侧的“显示敏感字段”可切换遮蔽状态，滚动表单时仍可操作。
点击右下角“保存配置”后写入 `.env.local` 并更新当前会话，新任务直接使用保存值。
关闭不保存。原文件保留为 `.env.local.bak`；完整优先级、备份和冲突处理见
[TUI 本地设置](CLI_Reference.md#tui-本地设置)。

同一窗口的“采集权限”页可检查主机条件并配置 perf / tcpdump。两个选项可独立勾选，也可同时选中，默认均选中；
选中显示高亮 `✓`，未选中显示空框。点击选项或聚焦后按空格切换。先预览操作，再在系统终端完成
sudo 授权；完成或取消后返回 TUI。配置会留存原权限，随后自动复查；它不会启动模型或发送通知。
权限操作预览在终端中居中显示；命令列表过长时可滚动，底部操作按钮保持可见。
依赖与权限范围见[最小权限安装](Getting_Started.md#最小权限安装)。运行采集、检查或其他任务时无法编辑这些配置。

设置页同时保留界面偏好：界面语言（简体中文 / English）、八种主题（深海蓝、纸白、石墨灰、松林绿、暮紫、琥珀、暖砂、雾蓝）、
日志保留行数（500 / 1000 / 3000 / 10000）、日志自动换行，以及是否显示底部快捷命令框。
默认主题在下拉列表及选中框中标注为“石墨灰 · 深色（默认）”。
修改当次生效，点击“保存设置”后，下次启动沿用。
按 `F2` 打开设置，在“界面语言 / Language”选择 `English` 即可切换为英文；
页面、表单、提示、确认弹窗和监控状态同步切换，当前输入、预设、日志选区和已读取摘要保留。
日志中的原始子进程输出保留原文，模型 ID、路径、命令和实验数据不做翻译。
默认使用简体中文；已有设置文件缺少语言字段时也使用简体中文。
换行设置会重新排布已有日志；行数上限按原始文本行计算，调整后立即裁剪较旧内容。
“恢复界面默认”先恢复当次显示，再点击保存即可保留。

## 实验配置与自动记忆

采集参数留在实验页。点击“高级参数”，切换到 batch size、Warmup、Repeat、请求窗口、采样
频率、连接/读取超时、可选固定 CPU 集合、分析器和任务覆盖参数等选项；点击“返回基本配置”回到模型和资源矩阵。
Warmup 和 Repeat 分别输入，次数、Hz 和 s 放在输入框右侧。采样频率、Idle 基线、冷却时间和请求超时
以两列排列，窄终端自动变为单列；整数不显示多余的 `.0`，已有小数精度保持不变。
拆分显示不改变命令参数或配置文件中的 `warmup`、`repeat` 等字段。
高级参数内的“记住实验配置”会保存当前实验表单，下次打开此项目时自动填入。
“识别覆盖 → 模型接口声明”接收本地 JSON 路径，运行采集和最大输入探测均传入 `--model-spec`。
例如 Ultravox 可填 `examples/multimodal/ultravox.model.json`；文件缺失或声明不合法时在启动前报错。
字段随实验配置保存，切换界面语言保留路径；协议与离线依赖见[模型声明](Runtime_Compatibility.md#本地模型声明与自定义-pipeline)。
模型 ID 会在确认启动采集或最大输入探测时自动记住，无需点击保存；即使任务失败或被终止，
下次打开仍会填入该模型。仅修改输入、预览命令或取消确认不会更新记录。
模型的填入顺序为：命令行 `--model` → 最近启动的模型 → 手动保存的实验配置。
`--preset` 优先于保存的其他实验参数，并保留按上述顺序选出的模型。运行任务期间，配置控件暂时锁定。

### 结果路径

“绘图工具”的“结果 CSV”和“补采工具”的“结果目录”分别自动记忆，下次启动直接恢复。
确认采集时仅记住模型；本次输出目标保留在运行配置中。结束后只有确认属于本次 attempt 的新 CSV 才更新结果路径；
预检失败不会用目标目录中的旧 CSV 覆盖历史选择。仅有已完成 case 时，保留目录显示在监控详情中，便于续跑。
成功读取摘要或启动绘图时记住使用的 CSV，确认启动补采或补采计划时记住使用的目录，
按钮和快捷命令都适用。仅编辑输入框、无效路径或取消确认不会覆盖记录；最大输入探测不改动这两个结果路径。
路径保存只发生在子进程启动前或结束后、手动读取摘要后；测量期间禁用摘要读取。
统计页初始带入最近的结果 CSV；完成采集或更换已确认的 CSV 时，未另行编辑的统计路径会随之更新。
可直接编辑统计路径；手动输入的报告路径在切页和语言切换时保留，不另存为实验配置。
启动窗口统计会记住使用的 CSV，打开 JSON 报告不会改变采集、绘图或补采路径。

### 设置文件

设置文件按项目目录隔离，保存在 `$XDG_CONFIG_HOME/acprof/<项目路径哈希>/tui.json`；
未设置有效的 `XDG_CONFIG_HOME` 时使用 `~/.config/acprof/<项目路径哈希>/tui.json`。
设置页会显示完整保存位置。文件仅包含界面偏好、显式记住的实验默认参数、最近启动的模型 ID 和结果路径；
凭据由“连接与权限”写入独立的 `.env.local`。设置文件损坏时，界面提示并使用默认值，自动记忆不会覆盖原文件；
下一次主动保存设置后恢复自动记忆。自动记忆保存失败会提示，但不阻止任务启动或结果读取。

## 日志查看与复制

监控页显示状态摘要和日志；阶段、当前 case、已完成数量和资源配置集中在顶部，剩余空间用于日志。
“警告 / 错误”标签在窄窗口中保持单行，计数显示在右侧。
日志区域紧接状态摘要，复制、回到底部、放大和清空操作集中在底部工具栏。
状态摘要、日志区域及其工具栏统一融入页面背景，日志保留焦点边框、文本选区高亮和可辨认的滚动滑块。
日志是只读文本：鼠标拖动选择，双击选词，`Ctrl+A` 全选，`Ctrl+C` 或“复制选区”复制。
复制保留原始文本，屏幕上的自动换行不会变成额外换行；系统剪贴板通过终端的 OSC 52 通道写入，
需要终端允许该功能。点击“放大日志”、按 `F8` 或输入 `/log` 可铺满终端，`Esc` 或“返回监控”恢复。
放大时仍可复制、清空和终止任务。滚动查看历史或选择文字后暂停跟随，新增日志继续保留，
点击“回到底部”恢复自动跟随。滚动条使用与主题一致的整格滑块，避免半格字形形成黑色断带。

## 测量期间的界面行为

正式采集通过版本化边界事件控制静默状态，普通日志文字不再决定窗口开关。
停止、回调异常和卸载共用 SIGINT（30 秒）→ SIGTERM（5 秒）的清理策略；未确认退出时
显示“清理未完成”与 PID，保持忙碌，可以再次停止，不会提前显示完成或启动第二个任务。
默认不自动 SIGKILL；协议和退出限制见[进程与界面边界](Profiling_Protocol.md#进程与界面边界)。


界面不会重写采集逻辑，而是启动现有 `run.py`、`probe.py`、`plot.py`、`stats.py` 和 `profile.py`。为了降低
对能耗与延迟实验的影响，正式 workload 窗口内停止常规日志重绘，不运行实时绘图，
也不轮询正在写入的 CSV；状态仅从已有进程输出中事件驱动更新。TUI 内运行时还会
禁用子进程的 tmux pane 捕获，避免把全屏 ANSI 重绘写进 `logs/terminal.log`（旧目录为 `tmux_all.log`）。论文复现仍可
直接复制界面显示的完整命令，在普通 CLI 或自动化脚本中执行。


## 下载与磁盘预检

实验参数中的“下载与 Model Store”提供下载源模式、`max-download`、Model Store 路径和容量上限，保存实验默认配置后会恢复这些字段。连接配置也可保存对应环境变量。开始准备后，在大下载前展示 expected / DIRECT / PROXY、模型缓存、runtime 来源与磁盘余量；DIRECT/PROXY 是预期分类，不是已验证的 VPN 分流。存在待下载量或未知量时弹出计划确认；预算未知/超限时先报错，不能通过确认绕过预算。该过程全部在正式测量前，测量窗口不扫描磁盘、不查询下载源。

下载完成后同一区域显示已校验的新增模型 payload、cache savings；未知 wire bytes 不显示成零。
“Model Store 占用与清理”先显示总量、各模型和 free space，再加载 LRU 删除预览。
若缓存锁由另一任务持有，面板显示等待原因；关闭按钮或 Esc 可以取消等待与扫描，无需等下载任务结束。
后台读取释放资源后关闭面板并恢复实验操作，避免残留扫描与随后启动的测量重叠。

清理仍需确认，删除前在锁内复检活动 lease、共享权重和批准范围，预览后新增的模型会保留。
实际删除已经开始时先完成锁内收尾，再处理关闭请求；运行和测量期间不能打开清理面板。

Model Store 清理命令和 lease/LRU 语义见[下载网络与 Model Store](Runtime_Compatibility.md#下载网络与-model-store)。真实终端效果需另验，headless 交互不代替 SSH/VS Code 客户端验证。
